# Agent 与 Harness 使用说明

本项目包含四套可复用能力：编码开发、验收文档编写、PPT 制作和概要设计文档编写。先按要完成的工作选择对应目录，再打开该目录的 README，按其中的目录说明和提示词案例操作。

## 四套能力分别做什么

| 目录 | 适合什么工作 | 主要能力 | 使用说明 |
|---|---|---|---|
| [`编码-开发执行-harness/`](编码-开发执行-harness/README.md) | 修改软件项目、实现需求、验证代码、调研技术方案。 | 管理需求、方案、开发任务、测试记录、项目分析、经验复用和任务收尾；业务代码仍在原项目仓库。 | [编码开发使用说明](编码-开发执行-harness/README.md) |
| [`验收-文档编写-harness/`](验收-文档编写-harness/README.md) | 编写或修订验收报告、总结、手册、测试文档等项目文档。 | 资料登记、文档范围与大纲确认、逐章写作、证据追踪、Word 复核、成果和知识管理。 | [验收文档使用说明](验收-文档编写-harness/README.md) |
| [`文档-PPT-Agent/`](文档-PPT-Agent/README.md) | 将项目材料整理成汇报、评审或验收用 PPT。 | 资料核对、逐页规划、视觉效果预览、原生可编辑 PPTX 构建、章节集成、渲染和视觉质检。 | [PPT Agent 使用说明](文档-PPT-Agent/README.md) |
| [`文档-概要设计-Agent/`](文档-概要设计-Agent/README.md) | 编写或修订软件概要设计、总体设计和技术设计文档。 | 合同/源码取证、需求追踪、模板与样本分析、提纲确认、分章写作、Word 生成和全页质检。 | [概要设计 Agent 使用说明](文档-概要设计-Agent/README.md) |

## 怎么选择

- 要改代码、做功能或验证实现：选**编码开发 Harness**。
- 要写验收报告、总结或操作手册：选**验收文档 Harness**。
- 要制作演示文稿：选**文档 PPT Agent**。
- 要写软件概要设计或总体技术设计：选**概要设计 Agent**。
- 如果既要写概要设计又要制作汇报 PPT，可分别使用对应 Agent；一份 Agent 的输出可以作为另一项工作的输入资料，但请分别维护各自工作区和交付状态。

## 快速开始

1. 在支持项目指令和文件操作的智能开发工具中打开要使用的子目录。
2. 阅读该目录的 `README.md`，了解工作区各目录的用途。
3. 按 README 中的示例发送对应提示词；项目资料可放入工作区指定资料目录，或登记为只读的外部路径。
4. 查看工作区状态、过程记录和最终成果目录，按阶段确认内容并提出调整。

| 任务 | 可直接尝试的提示词 |
|---|---|
| 开发需求 | `需求# 增加用户批量导入功能，支持 CSV 并提示错误行` |
| 验收文档 | `需求# 编写项目验收测试报告，覆盖本次已执行的功能测试` |
| 汇报 PPT | `新建一份PPT，名称为“项目验收汇报”，先整理资料并给我逐页目录确认` |
| 概要设计 | `新建概要设计文档，名称为“统一业务平台概要设计”` |

各目录还提供更完整的提示词表，涵盖调整、检查、交付等动作。编码开发 Harness 使用 `#` 提示词触发工作流；其余 Agent 也可用 README 给出的自然语言指令。

## 使用边界

资料和代码的读取/写入规则、确认节点及交付检查由各子目录自己的 `AGENTS.md` 和 Skill 规定。项目事实应来自对应项目资料；未经确认的信息不能当作事实。运行测试、发布服务、删除旧成果或执行其他有影响的动作，应遵循对应目录的授权规则。
