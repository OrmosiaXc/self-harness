# 专业可编辑 PPT

把 PPT 作为有事实来源、技术大纲、内容锁、视觉蓝图、共享构建契约、可编辑工程和验证证据的交付物。默认路径是：

`事实核对 → 技术大纲 → 全局契约 → CyberPPT 效果图 → 可编辑重建 → 父任务集成 → 全稿 QA`

## 启动

1. 读取根目录 `AGENTS.md` 和当前工作区状态。
2. 检查已有资料、PPT、模板、技术大纲、逐页目录、效果图、构建脚本、章节交付和 QA。
3. 新项目运行 `python3 agent.py new "<PPT名称>"`；已有目录禁止覆盖。
4. 根据输入和模式加载对应能力：
   - 效果图和视觉蓝图：`cyber-ppt`；
   - PPTX 输入或输出：`pptx` / `Presentations`；
   - 标题留白的可编辑内容页：`editable-ppt-pages`；
   - DOCX / PDF：`docx` / `pdf`；
   - 架构、流程和数据流：`architecture-diagrams`。
5. 从磁盘状态继续，不把聊天记录作为唯一事实来源。

## 运行模式

### `full-slide`

由同一任务构建完整页面，标题、页码和页眉页脚均在最终 PPTX 中。

### `content-only-integration`

用于后续合并或多章节并行开发。页面仍是完整 16:9，但子章节只构建内容区；标题区保持空白，标题、页码和全局元素由父任务统一添加。默认优先使用此模式完成可复用内容页。

详细规则见 [标题留白的内容页集成模式](references/content-only-integration.md)。

## 阶段 1：任务、资料与事实

在 `00-任务说明/制作任务.md` 记录场景、受众、页数、必须包含/删除/禁止/保持不变、构建模式、是否启用子章节任务会话、交付目录和版本规则。

读取 [资料与源码事实核对](references/source-and-code-grounding.md)：

- 建立资料使用清单和事实与证据台账；
- 区分已验证事实、文档陈述、源码现状、目标表达和待确认项；
- 源码核对入口、调用链、参数、处理、输出和异常，不只看 README；
- 无证据的准确率、容量、时延、稳定性和业务成效不得写成事实；
- 外部资料和源码目录保持只读。

## 阶段 2：技术大纲与逐页规划

先生成 `03-内容规划/技术大纲.md`，明确：

- 总体业务目标和技术主线；
- 章节 ID、章节目标、输入资料、输出结论和依赖；
- 稳定页面 ID，例如 `C06-S03`；
- 父任务保留的封面、目录、过渡、跨章节页和总结页；
- 可并行章节与必须串行的跨章节依赖。

再读取 [内容规划与受众表达](references/content-and-audience.md) 和 [逐页内容目录模板](templates/PPT逐页内容目录模板.md)，生成逐页目录与 `页面标题映射.md`。每页只承担一个主要问题，并包含核心结论、可见内容、证据边界、建议视觉和演讲提示。

用户要求先确认目录时，技术大纲和逐页目录确认前不得生成正式效果图或 PPTX。章节或页数变化时，先更新稳定页面 ID、标题映射和所有受影响任务包。

## 阶段 3：全局构建契约

读取 [全局构建契约](references/shared-build-contract.md)，使用 [全局构建契约模板](templates/全局构建契约模板.yaml) 冻结：

- 画布、安全区、标题区、内容区和页脚区；
- 中文/英文字体、回退字体和字号层级；
- 主色、辅助色、强调色、状态色和颜色语义；
- 网格、间距、卡片、流程、架构、表格、图表和图标规则；
- 父任务与子章节的对象所有权；
- 效果图、PptxGenJS、结构检查、渲染和交付标准。

契约状态为 `locked` 并记录版本或哈希后，才能下发子章节任务。子章节不得私改契约；偏差必须退回父任务审批并同步所有受影响章节。

## 阶段 4：父任务与子章节编排

读取 [父任务与子章节并行编排](references/parallel-chapter-orchestration.md)。

只有用户明确要求任务会话拆分，或制作任务中启用 `parallel_chapters` 时，才创建独立任务会话；否则按相同任务包顺序执行。

父任务：

1. 维护技术大纲、全局契约、页面标题映射和调度台账；
2. 使用 [子章节任务包模板](templates/子章节任务包模板.md) 下发自包含任务；
3. 给每个章节独立的资料索引、事实台账、内容锁、效果图、构建和 QA 目录；
4. 组织视觉确认、接收章节交付、添加全局元素并完成最终集成。

子章节任务：

- 只写自己的 `chapters/<chapter-id>/`；
- 只处理任务包中的页面 ID 和资料边界；
- 继承同一契约版本；
- 不修改其他章节、最终页码、标题、页码或全局页眉页脚；
- 不再次拆分任务；
- 章节内部仍按页顺序完成效果图到可编辑重建闭环。

## 阶段 5：CyberPPT 效果图

读取 [CyberPPT 效果图到可编辑 PPT 双阶段流程](references/cyberppt-blueprint-to-editable.md) 和 [视觉设计规范](references/visual-design.md)。

1. 为每页建立 `slide_content_lock`。
2. 先生成代表页风格样张；用户指定风格时按指定方向收敛。
3. 生成整套 16:9 效果图，不只做少量代表页。
4. `content-only-integration` 模式必须保留空白标题区，只在内容区绘制；页码、页脚和底部总结由父任务控制。
5. 效果图确认后建立 `blueprint_component_signature`、`visual_element_registry` 和逐页重建计划。
6. 记录确认状态；未确认的效果图不得进入正式可编辑构建。

效果图必须使用真实内容，不伪造数据、曲线和界面，不把项目色值固化为通用默认。

## 阶段 6：可编辑重建

读取 [可编辑构建规范](references/editable-build.md) 和 [依赖与渲染环境](references/dependencies.md)。

- 使用 PptxGenJS；
- 标题、正文、流程、卡片、矩阵、表格和图表使用 PowerPoint 原生对象；
- SVG、截图和照片是局部、独立、可替换素材；
- 不使用整页效果图、整页截图或 HTML 截图替代可编辑页面；
- 文本框启用缩小适配并使用固定边距；
- 每页保存页面清单、对象坐标、内容锁、效果图、渲染图和演讲者备注；
- `content-only-integration` 模式下所有子章节对象必须位于内容区，标题区和父任务页脚区不得有可见对象；
- 页面级对照和 QA 通过后再构建下一页。

技术页面向管理者采用“目的—流程—结果—边界”，算法和代码名只作为必要依据。

## 阶段 7：章节验收与父任务集成

子章节使用 [子章节交付清单](templates/子章节交付清单模板.md) 提交任务包、契约快照、事实台账、内容锁、效果图、组件签名、PPTX、源码、素材、页面清单、渲染和 QA。

父任务：

1. 按契约版本、页面 ID、内容零漂移、视觉语义和可编辑性验收章节；
2. 按 `页面标题映射.md` 排序，不靠文件名或自然顺序推断页码；
3. 保留原生对象和备注，不缩放、不截图、不栅格化章节页；
4. 添加统一标题、章节标识、页码和全局页眉页脚；
5. 使用 [父任务集成验收模板](templates/父任务集成验收模板.md) 执行全稿回归。

未通过的章节退回原章节任务修订，不在集成阶段临时重排掩盖问题。

## 阶段 8：结构与视觉 QA

读取 [质量检查与版本交付](references/qa-and-versioning.md)。

1. 检查画布边界、标题保留区、页脚区和文字溢出候选。
2. 运行 `scripts/validate_editable_pptx.py` 检查页数、备注、标题、可编辑对象、自动适配、越界、整页栅格图片和集成区域。
3. 将 PPTX 渲染为 PDF、逐页 PNG 和总览图。
4. 对章节效果图与重建页做并排或叠图检查。
5. 检查全部页面和跨章节一致性，列问题、修复并重新渲染。
6. 至少完成一次“发现问题—修复—复验”；有条件时交给未参与构建的独立审阅者。

脚本成功或 PPTX 能打开不能替代视觉验收。

## 阶段 9：修订、交付与清理

局部修订只修改目标页及必要的内容锁、效果图、标题映射、备注、验证和版本说明。若改变全局契约，必须广播到所有受影响章节并完成回归。

交付至少包含：

- 最终 PPTX、子章节可合并 PPTX 和逐页目录；
- 技术大纲、全局构建契约、页面标题映射和任务拆分记录；
- CyberPPT 效果图、组件签名和视觉元素登记；
- PptxGenJS 源码、资源与依赖；
- PDF、逐页 PNG、总览图、结构报告和视觉 QA；
- 版本、哈希、演讲者备注和会话交接。

用户明确要求清理旧版时，先复制并验证新版，再只删除精确列出的被替代对象并记录不可恢复性。
