# 内容规划与受众表达

## 叙事设计

正式汇报优先采用：

1. 结论与范围；
2. 已形成的主体成果；
3. 系统如何协作；
4. 关键计算或业务如何运行；
5. 如何验证；
6. 交付了什么；
7. 有哪些边界和待确认事项。

章节不是越多越好。每个章节都应回答一个明确问题，并在页数约束内保持前后平衡。

## 每页内容模型

- 标题：直接表达本页结论或问题。
- 核心结论：一句话，说清“本页要让听众记住什么”。
- 主体：3～5 个信息单元，或一条清晰流程。
- 证据：来源、指标、截图、代码依据或正式边界。
- 汇报提示：讲解顺序、容易误解之处和下一页衔接。

## 领导汇报的技术降维

优先讲：

- 业务目的；
- 输入如何变成结果；
- 质量如何控制；
- 结果如何被使用；
- 什么不能由系统单独保证。

少讲：

- 连续的类名、函数名、变量名；
- 没有业务解释的公式和参数；
- 过细的文件格式和内部目录；
- 不影响决策的实现分支。

算法名可以保留，但应附一句作用说明。例如：

> 使用稳健异常值筛选，降低少量异常观测对整体结果的影响。

## 措辞规则

- 直接表达事实和边界，不使用“领导关注”“请领导放心”等对象标签。
- “已形成”“已完成”“已通过”要说明适用范围和证据。
- 不把测试记录通过写成正式专家验收已通过。
- 不把辅助分析写成唯一决策依据。
- 不使用含糊口号替代输入、处理和输出。

## 页数调整

新增章节或扩展页数时：

1. 先计算全稿页数；
2. 检查章节比重；
3. 合并重复结论；
4. 为复杂流程保留足够页数；
5. 更新所有后续页码、目录、备注和验证规则。
