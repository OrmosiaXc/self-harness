# 父任务与子章节并行编排

## 目标

长篇技术 PPT 先由父任务统一规划，再按子章节拆成相互独立的任务会话并行开发。并行只提高产能，不改变内容确认、效果图确认、可编辑重建和渲染 QA 的质量门。

只有用户明确要求任务会话拆分或在制作任务中启用 `parallel_chapters` 时，才创建独立任务会话；否则使用相同任务包在当前会话顺序执行。

## 父任务职责

父任务是唯一的全局事实来源，负责：

1. 生成并确认技术大纲、章节边界、稳定页面 ID 和页面标题映射；
2. 建立并冻结全局构建契约；
3. 给每个子章节下发自包含任务包、资料边界、页面范围和验收标准；
4. 汇总各章节效果图，组织统一视觉确认；
5. 接收已通过章节 QA 的可编辑页面，完成标题、页码和全局元素集成；
6. 执行跨章节一致性检查、全稿渲染、回归修复和最终交付。

父任务不得把关键规范只留在聊天中。所有共享规则必须写入磁盘，并在任务包中携带契约版本或哈希。

## 子章节职责

每个子章节任务只拥有自己的章节目录，并建立独立数据体系：

```text
chapters/<chapter-id>/
├── 00-task/              # 子章节任务包、范围和契约快照
├── 01-sources/           # 资料索引，不复制不必要原始资料
├── 02-evidence/          # 事实与证据台账、冲突和待确认项
├── 03-content/           # 子章节大纲、逐页目录、内容锁
├── 04-blueprints/        # CyberPPT 效果图、组件签名、确认状态
├── 05-build/             # PptxGenJS 源码、素材、页面清单
├── 06-qa/                # 结构报告、逐页渲染、对照图、QA 报告
└── 07-delivery/          # 可合并 PPTX、清单和交接说明
```

子章节任务必须：

- 只使用任务包列出的页面 ID、资料和边界；
- 继承全局画布、字体、色板、网格、组件和区域规则；
- 自己维护本章节的资料索引、事实台账、内容锁、效果图和构建状态；
- 在本章节内逐页完成效果图到可编辑重建闭环；
- 不修改其他章节、父任务契约、最终页码、全局标题、页码或页眉页脚；
- 不再次拆分子任务，保持单层扁平协作；
- 发现冲突时提交偏差申请，不自行改变全局规则。

## 拆分条件

适合并行的子章节必须满足：

- 章节目标和页面边界清楚；
- 主要资料集合可分离；
- 章节之间没有未解决的内容依赖；
- 全局契约已经冻结；
- 页面 ID 稳定，即使最终页码变化也不影响文件命名。

以下内容不拆给子章节：封面、目录、章节过渡、全稿总结、统一标题与页脚、跨章节对比、最终合并和全稿 QA。它们由父任务负责。

## 下发任务包

父任务下发的提示必须是自包含的，至少包含：

- 任务名称、章节 ID、页面 ID 列表、目标受众和业务目标；
- 允许读取和写入的绝对路径；
- 资料索引与事实边界；
- 全局构建契约路径、版本和不可变字段；
- 页面标题映射路径，但明确标题由父任务拥有；
- 内容、效果图、可编辑性和 QA 的退出条件；
- 明确禁止项和偏差处理方式；
- 交付目录、交付清单和安全重启文件。

## 并行与同步

父任务可以同时运行多个子章节，但只有一个全局契约版本处于 `locked`。修改契约时：

1. 暂停接收新章节交付；
2. 记录版本差异和受影响章节；
3. 向所有活动任务下发同一更新；
4. 子章节重新渲染受影响页面；
5. 父任务验收全部章节的新契约版本后恢复集成。

不要让不同任务靠彼此聊天同步。共享状态只通过父任务和磁盘文件传递。

## 父任务验收

每个子章节必须同时提交：

- 章节任务包与契约快照；
- 资料索引、事实台账和内容锁；
- 已确认效果图、组件签名和元素登记；
- 可编辑 PPTX、PptxGenJS 源码和素材依赖；
- 页面清单、结构检查、逐页渲染和修复复验记录；
- 已知边界、偏差和未决项。

父任务先检查契约版本和页面 ID，再检查内容、视觉和结构。未通过的章节退回原任务修订，不在集成阶段临时重排。
