## 历史 QA 限制

提炼时，工作区内下列 PPT QA 记录正文均为 0 字节，无法恢复其中的历史回答：

- 验收汇报 PPT 生成；
- PPT 逐页内容目录；
- PPT 目录章节重组；
- PPT 架构算法章节扩展；
- PPT 特殊计算与密评扩展；
- PPT 内容图片生成；
- PPT 蓝色风格调整；
- 可编辑 PPT 构建；
- 严谨风格 PPT 效果图；
- 严谨风格可编辑 PPT 重建；
- 层析成像 PPT 三页重写；
- 重写 PPT 第 21 至 23 页；
- 重写 PSD 趋势与反演页；
- 替换曲线示意；
- 重构反演逻辑。

因此，本 Agent 没有把缺失的 QA 回答当作可用事实，也没有虚构其内容。通用逻辑来自当前会话的用户原话和正式交付工程的可核查证据。

## 从需求变化提炼出的通用规则

| 真实变化类型 | 通用处理规则 |
|---|---|
| 先要目录、后做 PPT | 设置内容确认门禁 |
| 章节删除、新增和扩页 | 先重排目录、页码和总页数 |
| 先看效果图 | 设置独立的视觉确认门禁 |
| 风格从普通蓝色改为严谨蓝色 | 把配色与“正式、克制、可核查”的设计目标绑定 |
| 从效果图转可编辑 PPT | 视觉参考不能整页栅格化，需用原生对象重建 |
| 框体和字体错位 | 建立安全区、自动适配、坐标登记和渲染 QA |
| 技术页与代码不一致 | 核对入口、调用链、算法用途、输出和边界 |
| 技术页对领导过深 | 使用“目的—流程—结果—边界”，算法名降为依据 |
| 图示让人误解 | 删除无数据支撑的曲线，改用结构化说明或真实结果 |
| 禁止对象标签式措辞 | 直接表达事实、风险和边界 |
| 每次新版删除旧版 | 新版先复制验证，再精确删除被替代对象 |
| CyberPPT 效果图先于可编辑构建 | 整套效果图是视觉基准，确认后才用原生对象重建 |
| 技术大纲按子章节并行 | 父任务冻结页面 ID 和契约，子章节使用独立数据、构建和 QA 目录 |
| 多任务仍需风格一致 | 字体、色板、网格、组件和区域由父任务通过全局构建契约一次下发 |
| 子章节只构建内容 | 保留完整画布和空白标题区，不把标题空间扩给正文 |
| 标题后续集成 | 页面标题单独维护映射，最终页码和标题由父任务添加 |
| 子章节交付需要可合并 | 禁止整页截图和缩放导入，保留原生对象与备注并执行集成回归 |

## 未固化的项目特例

具体项目名称、单位名称、页码、算法目录、测试数量、交付文档数量和视觉色值都没有写成通用强制事实。当前会话中的蓝白橙方向和品牌色值属于项目级视觉 token，只应写入对应项目的全局构建契约，不应影响其他 PPT 项目。
