# CyberPPT 效果图到可编辑 PPT 双阶段流程

## 适用范围

新建正式 PPT 时，默认先用 CyberPPT 形成整页效果图，再依据已确认效果图重建可编辑 PPTX。效果图是视觉规格和验收基准，不是最终页面素材。

若用户明确跳过效果图，可以连续推进，但仍需保存视觉规格、页面内容锁和重建计划。

## 阶段 A：内容与效果图

1. 基于事实与证据台账生成技术大纲和逐页目录。
2. 为每页生成 `slide_content_lock`，固定页面目标、可见文本、证据边界和视觉语义。
3. 建立全局构建契约，锁定画布、页面区域、字体、色板、间距、图表、图标和页脚所有权。
4. 使用 CyberPPT 先做 8 种方向的风格样张或用户指定风格；锁定后再生成整套效果图。
5. 对效果图逐页检查：信息结构、内容密度、对齐、留白、文字换行、颜色语义、品牌一致性和标题保留区。
6. 只有效果图获得确认，或用户明确授权无需逐页暂停时，才进入可编辑重建。

效果图必须使用真实页面内容，不使用 lorem ipsum，不伪造指标、曲线、界面或结论。项目指定色值只进入该项目的全局构建契约，不固化为通用默认色。

## 阶段 B：视觉规格冻结

效果图确认后，为每页登记：

- `blueprint_component_signature`：页面类型、区域、组件、相对层级、颜色语义、字体层级和关键对齐线；
- `visual_element_registry`：每个视觉元素的业务含义、表现形式、位置和可编辑重建方式；
- `page_manifest`：页面 ID、章节 ID、标题映射、证据、素材、效果图、构建脚本、渲染图和 QA 状态；
- `reconstruction_plan`：哪些内容用文本框、形状、表格、图表、SVG 或可替换图片重建。

效果图确认后禁止“顺手优化”已锁定内容。需要改动时，先更新内容锁和确认记录，再重新生成受影响效果图。

## 阶段 C：可编辑重建

1. 使用 PptxGenJS 构建，不使用整页截图、HTML 截图或效果图整页铺底。
2. 标题、正文、卡片、流程、矩阵、表格、图表和基础图形使用 PowerPoint 原生对象。
3. 复杂装饰或图标可用 SVG；截图和照片只作为独立、可替换的证据素材。
4. 每页按 `内容锁 → 效果图 → 组件签名 → 原生对象 → 渲染对照 → 修复复验` 的顺序单页闭环。
5. 逐页生成本地差异叠图或并排对照，检查内容一致性和视觉接近度。
6. 通过页面级 QA 后才能进入下一页；子章节并行时，每个子章节内部仍按页顺序构建。

## 双重质量门

最终 PPTX 同时满足：

- 信息层可编辑：核心内容不是整页位图，文本和图形可选择、可修改；
- 视觉语义一致：效果图中的层级、强调关系、结构和阅读路径在 PPTX 中得到保留；
- 内容零漂移：最终可见内容与 `slide_content_lock` 一致；
- 结构可验证：页数、备注、边界、自动适配、禁止项和栅格化检查通过；
- 渲染可验收：全页 PNG、总览图和至少一次修复复验完成。

## 确认策略

- 内容确认点：技术大纲、章节、页数、逐页标题和核心结论。
- 视觉确认点：代表页风格和整套效果图。
- 可编辑验收点：逐页重建和渲染对照。
- 集成验收点：父任务合并标题、页码和全局页眉页脚后的全稿回归。
