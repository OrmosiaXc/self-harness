# PPT 制作阶段与状态机

## 状态

`received → sources_ready → technical_outline_ready → outline_confirmed → contract_locked → chapter_tasks_ready → blueprint_ready → blueprint_confirmed → chapter_building → chapter_qa → integrating → integration_qa → completed`

失败或等待时使用：

- `blocked`：缺少会显著改变结果的用户选择或关键外部条件；
- `partial`：只完成部分页、部分章节或部分验证；
- `needs_revision`：已有成果但 QA 或用户反馈要求继续修改。

## 阶段门禁

| 阶段 | 必备输入 | 产物 | 退出条件 |
|---|---|---|---|
| 任务定义 | 用户请求、已有材料 | 制作任务、约束清单 | 受众、范围、模式、页数和确认方式明确 |
| 资料识别 | 文档、代码、旧稿、数据 | 资料清单、事实台账 | 关键结论有证据状态 |
| 技术大纲 | 事实台账 | 章节边界、稳定页面 ID、依赖关系 | 用户确认 |
| 全局契约 | 已确认技术大纲 | 区域、字体、色板、组件、所有权和 QA | 状态 locked，有版本或哈希 |
| 子章节拆分 | 技术大纲、全局契约 | 自包含任务包、调度台账 | 写入范围无重叠、依赖可控 |
| CyberPPT 效果图 | 内容锁、全局契约 | 整套效果图、组件签名 | 用户确认或记录无需暂停 |
| 章节可编辑构建 | 已确认效果图 | 子章节 PPTX、脚本、备注 | 章节结构与视觉 QA 通过 |
| 父任务集成 | 已验收章节 | 标题、页码、全局元素、完整 PPTX | 标题映射和契约一致 |
| 全稿质量检查 | 集成 PPTX | PDF、PNG、总览、QA 报告 | 修复复验通过 |
| 交付 | 已验证成果 | 正式版、版本和哈希 | 交付核对完成 |
| 清理 | 用户明确授权 | 删除记录 | 新版已验证且目标精确 |

## 长任务规则

1. 每完成一个阶段更新 `当前状态.md`、`长任务计划.md` 和 `会话交接.md`。
2. 父任务同一时间只保留一个全局活动阶段。
3. 子章节构建阶段可同时存在多个独立任务，但每个子章节只保留一个活动页面。
4. 用户插入局部调整时，先保存当前安全重启点，再进入修订分支。
5. 页面目录、契约、效果图、构建代码和交付版之间使用版本号或哈希关联。
6. 若变化影响全局契约，父任务提升版本并向所有受影响章节同步。
7. 聊天内容是沟通媒介，磁盘状态才是跨会话事实来源。

## 父子状态

父任务状态记录技术大纲、契约、标题映射、章节任务、集成和最终 QA。子章节状态只记录本章节资料、内容锁、效果图、页面构建和章节 QA。

子章节状态不得覆盖父任务状态；父任务也不得把子章节内部工作细节当作已完成，必须以交付清单和验收证据为准。
