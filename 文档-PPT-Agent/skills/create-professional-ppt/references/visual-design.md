# 视觉设计规范

## 总体原则

视觉服务于判断和记忆。正式验收与领导汇报应体现克制、秩序、证据感和可核查性，避免随意拼贴、装饰性噪声和模板化 AI 痕迹。

## 画布与安全区

- 默认 16:9；
- 四周至少保留约 0.5 英寸安全边距；
- 页脚设置独立保护区，正文不得侵入；
- 卡片和列之间使用固定间距；
- 同类对象统一宽度、基线和内边距。

多章节项目必须在全局构建契约中用英寸固定标题区、内容区和页脚区。子章节不得根据单页内容自行移动区域边界。

## 信息层级

1. 章节标识和主标题；
2. 一句核心结论；
3. 流程、矩阵、表格、图表或证据；
4. 边界、来源和页脚。

正文左对齐，标题和关键数字可居中。不要依赖细线装饰标题；用留白、色块和字号形成层级。

## 配色

根据主题选择主色，不机械默认蓝色。正式科技和验收场景可使用低饱和深色主调、浅色内容背景和单一强调色。

颜色需要有语义：

- 主色：结构和重点；
- 绿色：通过或正常；
- 红色：风险、异常或边界；
- 灰色：辅助信息；
- 不因“看起来醒目”给未验证类别使用红色或绿色。

## 版式选择

- 结论页：大结论 + 3～4 个证据卡片；
- 架构页：分层、边界、参与者和横向保障；
- 流程页：4～6 步主流程 + 异常回路；
- 算法页：业务问题 + 处理链 + 输出 + 质量控制；
- 数据页：真实图表或大数字，不使用伪造趋势；
- 交付页：生命周期、清单和服务边界。

每页至少有一个有解释价值的视觉元素，但不为了“有图”而加入无意义插画。

## 风格预览

先用代表页锁定方向，再生成整套 CyberPPT 效果图。代表页应覆盖不同信息类型，通常选择：

- 封面；
- 结论先行；
- 架构或业务流程；
- 算法或数据；
- 验证与交付。

预览检查：

- 是否符合场景；
- 标题是否足够明确；
- 信息密度是否适合投影；
- 图形含义是否无需猜测；
- 长中文是否出现拆词；
- 颜色是否误导；
- 是否有超框、贴边或视觉错位。

`content-only-integration` 模式还要检查：

- 标题保留区是否真实留空；
- 页面视觉重心是否在内容区内稳定；
- 内容是否错误上移占用标题区；
- 子章节是否误加页码、页脚、底部总结或 `So What`；
- 页面标题是否已进入父任务维护的独立映射文件。
