# 质量检查与版本交付

## 结构检查

至少检查：

- 页数和顺序；
- 逐页标题；
- 备注数量；
- 每页可编辑文本；
- 文本自动适配；
- 对象是否越界；
- 页脚保护区；
- 是否存在整页栅格图片；
- 占位符、禁用词和不应出现的单位名称；
- 本机绝对路径和内部构建信息；
- 构建阶段布局报告。
- CyberPPT 内容锁、效果图、组件签名和可编辑对象映射；
- 标题留白模式下标题区与父任务页脚区无子章节对象；
- 页面 ID、标题映射、契约版本和子章节交付一一对应。

使用 `scripts/validate_editable_pptx.py` 执行通用检查，并在项目层补充标题、禁用词和页数参数。

## 视觉 QA

完整流程：

1. PPTX 转 PDF；
2. PDF 转逐页 PNG；
3. 生成总览图；
4. 逐页检查；
5. 列出问题；
6. 修复；
7. 重新构建；
8. 重新渲染受影响页和全稿；
9. 记录最终结论。

子章节先完成章节 QA，父任务集成后必须再做一次全稿回归。章节 QA 不能替代跨章节字体、色板、网格、标题、页码、术语和内容密度一致性检查。

检查重点：

- 文字截断、拆词和超框；
- 文本与形状重叠；
- 箭头或线穿过文字；
- 页脚与正文碰撞；
- 间距不一致；
- 同类对象未对齐；
- 对比度不足；
- 图表标签和单位不清；
- 图示含义容易被误认为真实结果；
- 页面过密或空洞；
- 局部修改破坏相邻页衔接。

首轮“未发现问题”不是成功信号，应换一种缩放、总览和逐页视角再次检查。

## 独立复核

有可用独立 Agent 时，把渲染图片和预期页面说明交给未参与构建的审阅者，要求其假定存在问题并列出全部缺陷。构建者负责判断、修复和复验，不能把审阅意见未经核实直接写入最终报告。

## 版本

实质性变更应提升版本并记录：

- 版本号；
- 变更页；
- 变更原因；
- 来源或代码依据；
- 构建时间；
- 页数和备注数；
- 结构 QA；
- 视觉 QA；
- SHA-256；
- 被替代版本。

多章节项目还需记录：

- 全局构建契约版本或哈希；
- 子章节任务和交付版本；
- 页面标题映射版本；
- 父任务集成顺序和退回修订记录。

## 安全清理

当用户要求“每次更新删除旧版”时：

1. 在新目录生成，不覆盖旧成果；
2. 复制新版到正式目录；
3. 验证新 PPTX、工程、渲染结果、报告和哈希；
4. 列出旧版精确路径；
5. 删除旧版；
6. 再次列目录，确认只保留目标版本；
7. 在交付说明中记录删除内容和恢复可能性。
