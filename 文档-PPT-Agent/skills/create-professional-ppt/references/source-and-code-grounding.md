# 资料与源码事实核对

## 资料分类

对每项资料记录：

- 路径或名称；
- 类型：合同、需求、设计、实施、测试、用户材料、旧 PPT、图片、数据、源码、参考样例；
- 用途：事实、强制要求、结构参考、视觉参考、证据截图、背景信息或不使用；
- 可信度和日期；
- 冲突、缺失和版本关系；
- 允许读取和允许输出的边界。

## 证据优先级

没有用户另行指定时，优先考虑：

1. 用户最新明确要求；
2. 正式签署材料或已确认目录；
3. 实际源码、运行输出和测试记录；
4. 设计、实施和使用文档；
5. README、注释、界面文案和参考样例。

优先级不能替代冲突记录。较高优先级也可能只覆盖特定范围。

## 源码核对路径

对要进入 PPT 的模块至少回答：

1. 入口在哪里；
2. 输入是什么；
3. 主要处理步骤是什么；
4. 使用了哪些算法或策略；
5. 输出和中间产物是什么；
6. 参数、异常、质量控制和边界是什么；
7. 页面概括是否与实际调用顺序一致。

先检索目录和符号，再阅读入口与调用链。不要只依据文件名推断功能。

## 代码转汇报表达

| 代码层事实 | 领导表达 |
|---|---|
| 类、函数、参数 | 系统承担的处理步骤 |
| 模型或算法名称 | 用于解决什么问题 |
| 中间数组、文件 | 形成什么可核查证据 |
| 迭代与阈值 | 如何控制质量和风险 |
| 异常分支 | 什么情况下停止、降级或需要人工复核 |

推荐顺序：

> 先说明要解决的问题，再说明系统如何处理，然后说明形成的结果，最后说明适用边界。

## 防止错配

- 文档说“自动”而代码只执行预设轮次时，页面应写“按配置轮次执行”。
- 代码只产出辅助指标时，不写成最终业务判定。
- 没有真实样本、精度评估或签署结论时，不生成带真实感的结果曲线和百分比。
- 图示用于解释时，应明确标为“流程示意”“结构示意”或改用卡片、步骤和矩阵。
