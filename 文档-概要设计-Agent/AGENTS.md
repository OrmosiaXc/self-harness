# AGENTS.md

## 项目目标

维护一个用于生成、评审和修订中文软件概要设计文档的 Agent。普通使用者只操作 `workspaces/<文档名称>/` 中的任务、资料投递、调整意见和交付成果目录。

## Startup Workflow / Agent 工程启动流程

当任务是修改本 Agent 本身，而不是编写某个概要设计文档时：

1. 依次读取 `feature_list.json`、`progress.md` 和 `session-handoff.md`。
2. 运行 `./init.sh` 建立当前验证基线。
3. 同一时间只把一个功能标为 `in-progress`，修改后记录文件、决策、风险和验证证据。
4. 交接前重新运行 `./init.sh --full`，并同步更新三个状态文件。

## One feature at a time / 单功能推进规则

- Agent 工程维护一次只推进 `feature_list.json` 中一个未完成功能。
- 当前功能通过验证并写入证据后，才能关闭或切换到下一功能。
- 用户插入更高优先级任务时，先把当前工作项、文件和安全重启点写入交接文件。

## 运行时入口

当用户要求新建、编写、评审、修订或交付概要设计、总体设计或 HLD 文档时：

1. 完整读取 `skills/write-high-level-design/SKILL.md`。
2. 读取 `shared-library/08-经验回流/经验索引.md`，只按当前任务需要加载对应主题。
3. 读取当前工作区的 `编写任务.md`、`当前状态.md`、`长任务计划.md` 和 `会话交接.md`，从已有检查点继续，不依赖聊天记录恢复状态。
4. 按 Skill 的阶段路由读取所需参考文件，不一次加载全部参考。
5. 使用根目录 `agent.py` 执行确定性的新建、资料识别、样本蒸馏、提纲、检查点、修订、检查、分章预览、渲染和 Word 质检动作。
6. 使用 `agent/system.md` 和 `agent/policies/` 约束事实、假设、只读源码、输出位置、权限和人工确认。
7. 面向普通用户只说明任务、投递、调整、过程成果和交付成果目录，不要求用户操作内部目录。

## 关键边界

- 不把某个具体项目的资料写入 `skills/**/references/` 或 `shared-library/`。
- 不移动、重命名或修改用户投递的原始资料。
- 不把历史样例中的项目事实当作当前项目事实。
- 缺少证据时标记“待确认”“假设”或“TBD”，不得补写成既定事实。
- 参考样本先蒸馏标题、段落、表格、图件和篇幅特征，只继承形式，不继承项目事实。
- 叶子小节不得退化为一段概括或重复套话；章节深度错误未清零时不得生成正式版。
- 合同、已验证源码、目标设计和待确认内容必须区分事实强度；合同功能只能增加设计细节，不能遗漏。
- 外部源码目录只用于阅读、检索和验证。不得在源码目录生成分析报告、Markdown、Word、图片、缓存或临时文件。
- 用户指定成果目录时，正式 Markdown、DOCX 和图表可以发布到该目录；未明确授权时仍只写当前工作区。
- 用户要求逐章调整时只生成分章预览；没有明确合并指令，不主动覆盖或重建总文档。
- 正式成果不得包含本机绝对路径、Agent 内部文件名、参考样本禁用词或不必要的代码式英文标识。
- 参考材料的有效事实、需求、约束和可复用说明可以按证据强度进入正文；材料载体信息（文件名、本地路径、资料编号、投递目录和内部台账）默认不进入交付内容。
- 只有用户明确要求“本地资源依赖说明”时，才在任务配置中启用逻辑依赖清单；该开关不自动允许披露本机绝对路径。
- 技术类概要设计模式默认不包含数据库详细设计、部署实施、运行维护和用户操作内容；相关信息只保留必要的总体边界。
- 修改章节前创建快照；只重写受影响章节并同步更新追踪矩阵和质量报告。
- 长任务每完成一个阶段都更新状态、计划、产物和下一步；同一时间只保留一个活动工作项。
- `.agent/` 是机器状态目录，普通用户不操作。

## Stay in scope / 范围边界

- 文档任务的范围由 `编写任务.md`、合同、资料索引和用户最新明确要求共同限定。
- Agent 工程修改只处理当前功能及其必要依赖；发现相邻改进时记录到 `progress.md`，不得顺手扩大修改范围。
- 没有新的用户授权，不发送外部消息、不改变源码项目、不覆盖用户原始资料，也不把待确认内容提升为既定事实。

## 代码规范

- Python 使用类型注解和 `dataclass`，函数保持单一职责。
- 注释只解释隐藏约束或非显然原因，用户提示和错误信息使用中文。
- 不覆盖已有工作区；必须显式传入 `--force` 才允许覆盖 Agent 生成的骨架文件。
- 修订归档前比较章节哈希，发现影响分析之外的章节变化时停止归档。
- 路径操作必须限制在本 Agent 根目录和 `workspaces/` 内。

## Definition of Done / 完成定义

只有同时满足以下条件才能宣称交付完成：

1. 强制要求和合同条款均进入需求、设计章节和追踪矩阵。
2. 资料台账、源码理解、模板蒸馏、提纲、章节、问题假设和质量报告均已更新。
3. 正式稿不存在未接受的占位符、伪造事实、敏感配置、数据库详细设计、部署步骤或用户操作步骤。
4. 参考样本隔离、章节内容深度和正式成果泄漏检查通过。
5. DOCX 结构检查、全页渲染和逐页目视检查通过，最终产物位于用户确认的交付目录。
6. `当前状态.md`、`.agent/state.json` 和 `会话交接.md` 记录最终证据与安全重启点。

## End of Session / 会话结束流程

结束 Agent 工程维护会话前必须：

1. 运行 `./init.sh --full` 并记录命令、结果和仍需人工确认的项目。
2. 更新 `feature_list.json` 的状态与证据，保证最多一个功能为 `in-progress`。
3. 更新 `progress.md` 的已完成、下一步、风险和验证证据。
4. 更新 `session-handoff.md` 的文件清单、阻塞项、决策和安全重启步骤。
5. 确认工作区处于 clean、restartable 的可续作状态，再声明本轮完成。
