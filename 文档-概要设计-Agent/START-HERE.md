# 概要设计 Agent：从这里开始

普通使用者只需要操作 `workspaces/` 中自己的文档目录，不需要修改 `agent/`、`skills/`、`contracts/` 或 `.agent/`。

使用时把本目录作为 Codex 工作区打开，然后直接说：`新建概要设计文档，名称为“某项目概要设计”`。根目录 `AGENTS.md` 会引导 Codex 加载核心 Skill，不要求普通用户先安装全局 Skill。

## 最简流程

1. 对 Agent 说：`新建概要设计文档，名称为“某项目概要设计”`。
2. 在新建工作区的 `00-任务说明/编写任务.md` 填写基本信息。
3. 把项目资料放入 `01-资料投递/所有参考资料放这里/`。
4. 资料或源码需要保持原位时，把绝对路径写入 `01-资料投递/外部资料与源码索引.md`；这些路径只读。
5. 如果有参考文档，把它作为普通资料投递或登记只读路径。当前项目需求或事实材料中经验证的内容可以进入正文；历史样例只蒸馏章节、篇幅和图表形式。最终交付必须套用的 Word 模板放入指定模板目录。
6. 对 Agent 说：`资料已放好，先阅读源码和材料、更新理解台账，再生成提纲`。
7. 查看 `03-过程成果/01-当前提纲.md`，确认后让 Agent 编写。
8. 修改时只编辑 `04-调整意见/调整要求.md`，新增资料放入相邻目录。
9. 想逐章查看时说：`生成第 3 章 Word 预览，不要合并总文档`。
10. 完成后对 Agent 说：`生成正式交付版并完成 Word 全页检查`。

## 你真正需要看的文件

- 当前进度：`00-任务说明/当前状态.md`

- 资料如何使用：`02-资料识别/资料使用清单.md`
- 源码和材料结论：`02-资料识别/源码与材料理解台账.md`
- Word 模板规则：`02-资料识别/模板蒸馏规范.md`
- 参考样本规则：`02-资料识别/参考样本蒸馏规范.md`
- QA 经验候选：`02-资料识别/QA经验候选.md`
- 当前目录：`03-过程成果/01-当前提纲.md`
- 各章草稿：`03-过程成果/02-章节草稿/`
- 分章 Word 预览：`03-过程成果/08-分章预览/`
- 章节进度：`03-过程成果/00-章节索引.md`

## 资料不需要手工分类

所有普通参考资料都可以放到“所有参考资料放这里”；外部合同、材料和源码也可以只登记路径。Agent 会将来源识别为项目事实、强制要求、目录结构参考、内容参考、样式参考、正式交付模板或不使用，并生成可纠正的资料使用清单。分析结果不会写入源码仓库。

参考材料里的有效需求、事实和技术说明可以进入文档，但材料的文件名、本地路径、资料编号和内部目录默认不进入交付内容。如果确实需要在文档中列出本地资源依赖，只需对 Agent 说“添加本地资源的逻辑依赖说明”，无需手工修改内部配置。
