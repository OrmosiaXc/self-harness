# 概要设计 Agent 使用说明

这个 Agent 根据项目需求、合同、设计资料和源码，编写或修订软件概要设计文档，并生成 Markdown、Word 和质量检查记录。普通使用者主要操作 `workspaces/你的文档名称/`；`agent/`、`skills/`、`contracts/`、`shared-library/` 和 `.agent/` 是 Agent 内部规则或状态目录。

## 目录是做什么的

每份文档工作区位于 `workspaces/<文档名称>/`。

| 工作区目录 | 用途 | 你通常要做什么 |
|---|---|---|
| `00-任务说明/` | 文档名称、项目范围、章节配置、读者、格式和交付要求。 | 填写 `编写任务.md`；查看状态、计划和会话交接。 |
| `01-资料投递/` | 当前项目的合同、需求、设计、报告、源码索引和指定 Word 模板。 | 将普通文件放入资料目录；外部源码/资料可登记路径并保持原位。 |
| `02-资料识别/` | Agent 对资料分类、源码理解、模板/样本蒸馏、冲突和缺口的记录。 | 查看材料是否读过、事实依据是什么、哪些内容待确认。 |
| `03-过程成果/` | 当前提纲、章节草稿、追踪矩阵、问题假设、检查报告和分章预览。 | 确认提纲；审阅章节、进度和质量问题。 |
| `04-调整意见/` | 对提纲、章节或整稿提出的修改要求，以及新增材料。 | 写明修改位置、修改要求和依据。 |
| `05-交付成果/` | 最终 Markdown、Word 和正式交付文件。 | 从 `02-正式版/` 获取最终成果。 |
| `.agent/` | Agent 自动维护的状态、资料清单、快照和检查点。 | 普通使用者无需修改。 |

Agent 工程目录（本目录下，不在文档工作区内）：

| 目录 | 用途 |
|---|---|
| `agent/` | Agent 的总规则、写作/修订/评审流程和事实、安全策略。 |
| `skills/write-high-level-design/` | 概要设计工作流、参考规范、脚本、模板和质量检查能力。 |
| `contracts/` | 任务输入、文档、追踪、资料清单和评审报告的数据格式约定。 |
| `shared-library/` | 可跨项目使用的写作规范、标准章节、样式、术语、正式模板和经验。项目事实不放这里。 |
| `integrations/` | MCP、OpenAPI、A2A 等集成配置示例及权限说明。 |
| `evals/` | Agent 工作流回归案例和质量评价规则。 |
| `examples/` | 用户操作流程示例。 |

## 开始使用

在支持项目指令和文件操作的智能开发工具中打开本目录，然后发送：

> 新建概要设计文档，名称为“统一业务平台概要设计”

Agent 会创建工作区。之后填写 `00-任务说明/编写任务.md`，把资料放入 `01-资料投递/所有参考资料放这里/`。不方便复制源码或资料时，在 `01-资料投递/外部资料与源码索引.md` 登记路径；外部目录只读，分析结果写在文档工作区。

也可通过命令行创建：

```bash
python3 agent.py new "统一业务平台概要设计"
```

## 提示词和使用案例

| 想做什么 | 提示词案例 |
|---|---|
| 新建概要设计工作区 | `新建概要设计文档，名称为“统一业务平台概要设计”` |
| 阅读资料并生成提纲 | `资料已放好，请逐项阅读合同、设计和源码，更新理解台账、需求追踪和待确认问题，然后生成提纲，先不要写正文。` |
| 查看或调整提纲 | `请把提纲第4章拆为业务体系和数据体系两章，并更新章节边界和需求追踪。` |
| 确认提纲并开始编写 | `提纲确认，按当前版本开始逐章编写。缺少依据的内容列入问题与假设，不要推测成事实。` |
| 查看当前进度 | `请读取当前状态、长任务计划和章节索引，告诉我完成章节、未决问题和下一步。` |
| 预览单独章节 | `生成第3章的 Markdown 和 Word 预览，我先审阅这一章，不要合并总文档。` |
| 补充资料后重新识别 | `我新增了接口清单，请阅读新增资料，更新源码与材料理解台账，并检查影响哪些章节和追踪项。` |
| 修改已写章节 | `请按调整要求只修改第4章，保存修订前快照，并同步需求追踪矩阵、问题清单和质量报告。` |
| 检查概要设计内容 | `请检查合同需求覆盖、模块边界、业务/数据流程、技术选型理由和待确认项，列出问题并修复明确范围内的问题。` |
| 生成正式版并做 Word 检查 | `请先执行正式质量检查，再生成 Markdown 和 DOCX，渲染全部页面并逐页检查；修复问题后复验并更新质检报告。` |
| 确认逐页检查完成 | `我已经逐页检查渲染图片，请运行 qa --confirm-visual 固化本次视觉检查结论。` |
| 修订现有 Word 前检查 | `请先对这个 Word 执行编辑预检，报告文件占用、权限和保护状态；不要自动解除保护。` |

## 一份文档的制作顺序

```text
建立工作区 → 填写任务 → 投递资料 → 阅读并核对证据 → 生成提纲
→ 确认提纲 → 逐章编写 → 内容检查 → 生成Word → 全页检查 → 交付
```

提纲确认前，Agent 只整理资料和规划章节，不写正式正文。资料中的历史样例可以参考章节结构、图表形式和篇幅，不能照搬旧项目的事实、指标或系统名称。证据不足的内容标记“待确认”或列入问题清单。

## 概要设计章节怎么组织

默认可以选择“技术类概要设计”或“标准全量概要设计”。技术类概要设计按项目实际组织需求、总体架构、具名业务/技术体系、系统模块和技术路线；不会因为模板默认排除就丢掉合同要求。用户指定的目录和正式模板优先。

本项目通用要求的核心内容顺序为：

1. 需求分析：功能需求、性能需求。
2. 系统总体设计：建设原则、建设思路、总体架构、业务流程、数据流程。
3. 具名体系设计：说明体系目标、架构、模型、处理流程、状态异常和模块边界。
4. 系统详细设计：按系统域—子系统—模块展开，说明模块功能、流程、接口、输入输出和异常等。
5. 技术路线：说明为什么选、在哪里使用、何时不使用。

## 命令行操作

Agent 通常会自行调用命令。手动排障时可用：

```bash
python3 agent.py --help
python3 agent.py new "统一业务平台概要设计"
python3 agent.py inspect "统一业务平台概要设计"
python3 agent.py outline "统一业务平台概要设计"
python3 agent.py status "统一业务平台概要设计"
python3 agent.py validate "统一业务平台概要设计" --mode structure
python3 agent.py validate "统一业务平台概要设计" --mode final
python3 agent.py render-chapter "统一业务平台概要设计" --chapter 3 --format all
python3 agent.py render "统一业务平台概要设计" --format all
python3 agent.py qa "统一业务平台概要设计"
```

`render-chapter` 只生成单章预览；`render` 生成整份文档，应在确认正式合并后使用。`qa` 会检查 DOCX 并渲染页面；逐页人工检查后才能使用 `--confirm-visual`。更多参数见 `python3 agent.py <命令> --help`。

## 去哪里看结果

- 当前进度：`00-任务说明/当前状态.md`
- 章节目录：`03-过程成果/01-当前提纲.md`
- 资料与源码理解：`02-资料识别/源码与材料理解台账.md`
- 未决问题：`03-过程成果/04-问题与假设.md`
- 需求覆盖：`03-过程成果/05-需求追踪矩阵.md`
- 内容检查：`03-过程成果/06-质量检查报告.md`
- Word 页面检查：`03-过程成果/07-Word版式质检报告.md`
- 最终文件：`05-交付成果/02-正式版/`

更多规则见 [AGENTS.md](AGENTS.md)，操作流程见 [START-HERE.md](START-HERE.md)，公共模板与规范见 [shared-library/资源库说明.md](shared-library/资源库说明.md)。
