# 评审流程

1. 检查资料使用清单是否存在未确认分类。
2. 检查源码与材料理解台账是否覆盖索引中的每个来源、项目和功能域。
3. 检查合同、需求、架构决策、模块、接口、章节和验证方式之间是否可追踪。
4. 检查功能边界、数据边界、接口边界、外部平台边界和文档排除项是否一致。
5. 检查安全、性能、可靠性、可维护性、可扩展性和可观测性是否有机制与验证方法。
6. 检查叶子小节是否有至少两个有效正文块或足够的结构化内容，是否存在重复套话和过度碎片化标题。
7. 技术类概要设计模式检查是否误入库表字段、SQL、部署操作、运维步骤、用户点击说明或不必要的代码式英文标识。
8. 检查参考样本与指定模板是否已蒸馏，真实标题样式、目录、表格、图题、页眉页脚和字体是否符合规则。
9. 搜索本机路径、内部产物、参考样本禁用词、占位符、无依据数字、模糊主语、敏感信息和冲突术语。
10. 将问题分为错误、警告和提示，生成质量检查报告。
11. DOCX 渲染全部页面，检查缺字、溢出、截断、孤立标题、空白页、低清图片、图件穿线和目录错误。
12. 错误未清零或逐页目视检查未完成前不得生成“正式完成”状态。
