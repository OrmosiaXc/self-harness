# QA 经验回流流程

1. 从当前工作区 QA、调整记录和质量报告中识别重复问题，先写入 `02-资料识别/QA经验候选.md`。
2. 每条候选必须记录触发场景、问题表现、候选规则、适用范围和验证方式。
3. 将候选分类为：
   - 通用规则：跨项目适用且可以验证；
   - 项目偏好：只在当前项目或用户明确范围内适用；
   - 项目事实：合同、模块、指标、技术版本和业务结论。
4. 只有经人工评审接受的通用规则可以提升到 `shared-library/08-经验回流/`。项目偏好保留在工作区，项目事实保留在资料台账。
5. 提升时先创建独立主题文件，再向 `经验索引.md` 追加一行入口；索引保持有界，详细内容按需读取。
6. 当前用户指令、项目资料和工作区规则始终高于共享经验。不得把另一个项目的删除授权、项目名称、指标或技术结论继承到当前项目。
7. 新规则必须同时定义可执行检查、人工复核项或回归用例；不能验证的经验只保留为建议。
