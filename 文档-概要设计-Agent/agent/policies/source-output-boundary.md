# 源码、资料与成果目录边界

## 外部源码与资料

- 外部源码仓库、合同目录、验收材料目录和用户提供的索引文件默认只读。
- 可以执行搜索、读取、哈希、静态解析和只读构建信息检查；不得修改源码、配置、依赖锁文件或仓库状态。
- 不在源码目录生成 Markdown、DOCX、图片、日志、缓存、测试数据、虚拟环境或临时文件。
- 需要运行辅助脚本时，在工作区 `.agent/` 或系统临时目录创建，记录脚本用途和产物位置。
- 源码存在未提交修改时视为用户工作，不清理、不重置、不覆盖。

## 成果位置

- 默认成果位于当前文档工作区。
- 用户明确指定外部成果目录时，可以发布正式 Markdown、DOCX、图表和清单到该目录。
- 发布目录不得位于任何只读源码目录内部。
- 不自动删除历史成果。只有用户明确要求清理时，才先列出拟删除的 Agent 生成文件，再删除旧版并保留当前正式版。
- `编写任务.md` 的历史版本策略只定义项目偏好，不等于删除授权；不得继承其他项目的清理授权。
- 不移动、重命名或删除用户原始资料。

## 参考材料与正文

- 参考材料是取证和内容参照来源，不是交付文档的附带依赖。
- 强制要求和项目事实中经核验的实际内容可以进入正文；内容参考中可复用的技术解释只能在剔除历史项目事实并重新核验后改写进入。
- 文件名、本地路径、资料编号、投递目录名和内部台账名默认只出现在资料清单、追踪矩阵和 Agent 内部状态中，不出现在正式 Markdown、DOCX、图片替代文本或面向读者的附录中。
- 概述中的“参考依据”可写用户确认的法规、标准、合同或需求正式名称与版本，不写它们在本机的文件名和存放位置。
- 只有用户明确要求时，才将 `本地资源依赖说明`改为“写入逻辑依赖”。该说明可包含逻辑文件名、资源用途、必选/可选、版本和校验信息，但仍不得自动披露本机绝对路径。

## 敏感信息

- 不复制数据库口令、Token、密钥、私钥、Client Secret、真实内部地址、个人联系方式或未授权配置值。
- 代码中发现敏感值时只记录“存在敏感配置风险”和治理建议，不在台账或正式文档复现原值。
