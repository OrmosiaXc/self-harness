# 证据状态与正式措辞

| 状态 | 含义 | 正文措辞 |
|---|---|---|
| `S-已验证实现` | 源码、配置结构、接口或结果能够直接证明 | “系统采用”“系统实现”“模块通过……” |
| `C-合同要求` | 合同、工作说明书或强制要求明确规定 | “合同要求”“系统应提供” |
| `D-设计目标` | 详细设计或目标方案提出，但尚无实现证据 | “目标设计”“拟采用”“设计上应……” |
| `P-待确认` | 缺少源码、联调、部署、测试、截图或批准结论 | “待确认”“以联调/验收结果为准” |

## 使用规则

- 状态只进入资料台账、源码理解台账、问题清单和追踪矩阵，不进入正式章节标题。
- 同一结论有多类证据时分别记录，不用较弱材料覆盖较强事实。
- 合同功能必须全部进入追踪矩阵；缺少实现证据不等于可以删减，只能降低措辞强度。
- 详细设计中的候选技术、示例接口和目标架构不能在没有代码或环境证据时写成现状。
- 前端页面、外部平台、密码资源、供应链流水线等未在当前源码范围内时，明确写出证据边界。
