# 概要设计编写原则

1. 说明系统做什么、由哪些部分构成、各部分如何协作；可以引用关键源码证明现状，但不复制大段代码或退化为类清单。
2. 每个设计结论应能追溯到需求、约束或明确的架构决策。
3. 模块说明至少包含概述、功能架构、功能逻辑、业务流程、技术实现、数据与接口、异常与边界。
4. 接口说明至少包含调用双方、用途、协议、核心数据、异常和安全要求。
5. 数据内容至少包含分类、架构、存储职责、流向、生命周期、一致性和安全；数据库详细模型、库表字段和 SQL 由数据库设计文档承担。
6. 图和文字必须使用相同名称；一张图只表达一个主要视角。
7. 不确定内容进入问题与假设清单，不伪装成已经确认的事实。
8. 合同功能只增不减；已验证实现、合同要求、目标设计和待确认事项使用不同措辞。
9. 源码目录只读取证，成果写工作区或用户指定目录。
10. Word 正式稿必须套用或蒸馏指定模板，并完成全页渲染和逐页检查。
