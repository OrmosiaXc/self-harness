# 模块说明方法

模块章节优先回答以下问题：

- 模块概述是什么，承担什么业务目标？
- 功能架构包含哪些内部能力和协作方？
- 核心规则、状态和功能逻辑是什么？
- 业务流程的正常路径、分支和补偿是什么？
- 技术实现使用哪些组件、服务、算法或运行单元？
- 输入、输出、文件、消息和接口关系是什么？
- 异常、超时、幂等、权限、限制和证据边界是什么？
- 模块解决什么问题，不解决什么问题？
- 谁调用它，它依赖谁？
- 输入、输出和状态变化是什么？
- 正常流程、异常流程和降级策略是什么？
- 权限、审计和敏感数据要求是什么？
- 哪些容量、时延、可用性指标会影响设计？
- 后续详细设计需要继续明确什么？

历史项目中的模块名称、接口地址、技术版本和指标只能作为内容参考，不能直接成为当前项目事实。

系统概要设计按全部功能点逐模块展开。合同要求没有源码证据时仍保留模块，但使用“系统应”“目标设计”或“待联调”措辞。
