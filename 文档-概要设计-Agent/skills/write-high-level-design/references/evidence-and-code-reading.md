# 资料取证与源码阅读流程

## 适用场景

用户提供资料索引文件、多个合同/设计文档、Java/Python 或其他源码仓库、外部平台材料时，先完成本流程，再生成提纲或正文。

## 取证顺序

1. 读取用户当前任务中的强制要求和成果目录。
2. 读取资料索引文件，逐项确认路径、类型、用途、只读属性和可访问状态。
3. 阅读合同、工作说明书和验收要求，建立功能追踪编码。
4. 阅读详细设计和历史材料，区分业务目标、候选方案和当前项目事实。
5. 阅读正式交付模板，提取样式和篇幅约束。
6. 阅读源码、接口、配置结构和测试，验证当前实现。
7. 将冲突、缺失和证据状态写入台账，不静默融合。

## 源码阅读方法

### 项目级

- 识别构建文件、模块清单、语言版本、框架和主要依赖。
- 区分主应用、独立服务、算法项目、第三方 vendored 代码和未纳入聚合构建的组件。
- 记录入口、模块职责、运行边界和外部依赖。

### 功能级

对每个合同功能和主要业务模块追踪：

1. 调用入口；
2. 服务或算法主链路；
3. 输入和输出；
4. 数据、文件或消息状态；
5. 异常、超时和边界；
6. 查询、归档和审计；
7. 可验证证据文件。

### 算法级

每个算法至少记录：

- 入口脚本和调用方式；
- 输入文件、参数和前置依赖；
- 处理步骤、窗口、阈值和模型选择；
- 输出 CSV、JSON、图片、模型或过程报告；
- 平台如何准备、调用、解析、保存和查询；
- 算法适用范围、已知差异和待确认项。

### Java/平台级

至少确认：

- 控制器或任务入口；
- 调度、异步、并发和阶段状态；
- 数据准备；
- Java/Python、消息或外部服务契约；
- 结果解析、结构化指标和文件归档；
- 查询与可视化数据服务；
- 身份权限、安全审计和敏感配置治理。

## 台账结构

`源码与材料理解台账.md` 至少包含：

1. 结论摘要和系统闭环；
2. 证据状态规则；
3. 各源码项目的入口、核心逻辑、输出、平台用法和边界；
4. 平台技术基线与模块；
5. 合同功能追踪编码；
6. 两份或多份设计材料的使用原则；
7. 模板结构与样式结论；
8. 材料差异及处理决定；
9. 可直接进入正文的已验证事实；
10. 待确认清单；
11. 与最新 Plan、提纲和追踪矩阵的同步结论。

每次提纲或 Plan 发生实质调整后更新台账；替换旧版时保留单一当前版本，清理历史版本必须得到用户明确授权。

## 证据边界

- 前端源码不在范围内时，只确认后端数据服务，不宣称完整页面实现。
- 外部供应链、云平台、资源池、密码资源没有配置或运行记录时，只写合同要求或目标设计。
- 详细设计示例接口与实际 Controller 不一致时，概要设计描述接口类别，具体接口文档以代码重新生成或核对。
- 配置文件中的真实敏感值不得进入台账和正式文档。
- 外部源码目录只读，所有脚本、缓存和分析产物写到工作区 `.agent/` 或系统临时目录。
