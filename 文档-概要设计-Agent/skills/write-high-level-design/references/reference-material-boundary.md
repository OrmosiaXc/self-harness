# 参考材料内容与载体边界

## 核心判断

参考材料同时包含两层信息：

1. 材料内容：需求、事实、约束、流程、接口、设计方法和技术说明。
2. 材料载体：文件名、本地路径、资料编号、投递目录、源码位置和 Agent 内部台账。

默认规则是“吸收有效内容，隐藏材料载体”。不得把“参考材料不进入正文”误解为“参考材料中的实际内容不得使用”。

## 各类材料如何进入正文

| 材料用途 | 可进入正文的内容 | 不得直接进入正文的内容 |
|---|---|---|
| 强制要求 | 已核验的范围、功能、交付和验收约束 | 本地文件名、路径和未确认推断 |
| 项目事实 | 已验证的现状、接口、流程、模块和数据边界 | 源码文件位置、类/方法清单和敏感配置 |
| 目录结构参考 | 经当前需求裁剪后的章节组织方式 | 样例正文、项目事实和原章节文件名 |
| 内容参考 | 重新核验后的覆盖维度、通用方法和技术解释 | 历史项目名称、指标、版本、数据和结论 |
| 样式参考 | 编号、表格、图件、语气和排版方式 | 样例文字和技术结论 |
| 正式交付模板 | 版式、固定栏位和用户确认的固定文案 | 模板中遗留的旧项目内容 |

## 正文默认禁止项

- 本地文件名和绝对路径；
- Agent 生成的 `R-001` 类资料编号；
- “本文依赖某本地文件”、“资料位于某目录”等编写过程说明；
- `01-资料投递`、`.agent`、资料清单、蒸馏规范和理解台账等内部产物名称。

官方标准、法规、合同和需求文件如果需要作为“参考依据”展示，使用用户确认的正式名称和版本，不使用它在本机上的文件名或路径。

## 本地资源依赖说明例外

1. 默认保持 `编写任务.md` 中的 `本地资源依赖说明：不写入`。
2. 只有用户明确要求交付文档包含该说明时，才改为 `写入逻辑依赖`。
3. 逻辑依赖说明可写资源名称、类型、用途、必选/可选、适用版本和校验值。
4. 该例外不允许把资料编号和 Agent 内部目录写入正文，也不自动允许本机绝对路径。
5. 本地资源依赖说明是交付需求的显式例外，不得用它放宽参考内容的事实边界。

## 交付前自检

- 删除正文中的文件名、资料编号、本地路径和内部产物名称。
- 检查删除载体信息后，与之对应的有效需求、事实和设计约束仍然完整。
- 已启用逻辑依赖说明时，确认这是用户的明确要求，且未泄漏绝对路径。
