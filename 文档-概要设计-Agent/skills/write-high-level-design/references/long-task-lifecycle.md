# 长任务生命周期与会话交接

## 长任务原则

- 一个文档工作区同时只有一个活动工作项。
- 状态以磁盘文件为准，不依赖聊天上下文。
- 每个阶段有明确输入、输出、验证和下一步。
- 阻塞只记录真实阻塞；可以继续的缺失信息使用假设或待确认并推进。
- 所有生成物写工作区或用户指定成果目录，源码目录保持只读。

## 开始或恢复

按顺序读取：

1. `00-任务说明/编写任务.md`；
2. `00-任务说明/当前状态.md`；
3. `00-任务说明/长任务计划.md`；
4. `00-任务说明/会话交接.md`；
5. `.agent/state.json`；
6. 资料台账、当前提纲、章节索引、问题与假设和最新质量报告。

不要重做已经完成且有验证证据的阶段。

## 检查点内容

阶段切换、重要产物完成、用户调整和会话结束时记录：

- 当前活动工作项；
- 已完成步骤；
- 已生成或修改的文件；
- 已执行的验证及结果；
- 未解决问题或阻塞；
- 下一步唯一动作；
- 安全重启路径。

使用：

```bash
python3 agent.py checkpoint "<工作区>" \
  --step "完成模板蒸馏" \
  --status completed \
  --next "按已确认提纲编写第 1 章" \
  --artifact "02-资料识别/模板蒸馏规范.md" \
  --verification "模板哈希和参考渲染已检查"
```

## 推荐阶段

1. 任务和边界冻结；
2. 资料索引与源码范围登记；
3. 合同、详细设计和模板取证；
4. 源码与材料理解台账；
5. 合同功能和需求基线；
6. Plan 与提纲；
7. 分章正文；
8. 图表与交叉引用；
9. Markdown 结构评审；
10. DOCX 生成；
11. Word 结构检查与全页渲染；
12. 修复、发布和最终交接。

## 会话结束

在 `会话交接.md` 中写清：

- 当前状态；
- 本会话完成；
- 关键文件；
- 验证证据；
- 遗留问题；
- 下一会话第一步。

不要以“还在进行中”结束但不留下下一步，也不要在未通过质量门禁时把状态标成完成。
