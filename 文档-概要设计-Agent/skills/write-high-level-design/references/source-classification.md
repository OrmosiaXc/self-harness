# 资料分类规则

将每个文件分配到一种主要用途，并保留用户修正。

| 用途 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 强制要求 | 约束范围、交付和设计结论 | 与更高优先级要求冲突时静默覆盖 |
| 项目事实 | 支撑当前项目的事实陈述 | 超出资料内容进行补写 |
| 目录结构参考 | 参考章节名称、层级和顺序 | 复制其中正文、数据和结论 |
| 内容参考 | 参考说明角度、覆盖范围和表达方法 | 把历史项目事实写入当前项目 |
| 样式参考 | 参考字体、表格、编号、图表和语气 | 影响当前项目技术结论 |
| 正式交付模板 | 作为最终版式或内容载体 | 当作项目事实来源 |
| 不使用 | 明确排除 | 进入模型写作上下文 |
| 待确认 | 暂不确定用途 | 在确认前作为正式事实使用 |

优先级：当前用户要求 > 当前项目正式资料 > 可核验系统事实 > 企业标准 > 当前项目草案 > 历史样例 > 模型知识。

## 外部路径与源码

- 资料可以直接投递，也可以在 `外部资料与源码索引.md` 中登记绝对路径。
- 外部源码目录识别为“项目事实/只读来源”，目录本身不复制进工作区。
- 索引文件只说明读取顺序和用途，不能替代实际资料内容。
- 源码、接口和配置结构可以证明现状实现；README、注释和样例配置需要与执行路径交叉验证。
- 第三方 vendored 代码只证明依赖存在，不能据此声称项目调用了其全部能力。
- 外部路径不可访问、已移动或为空时记录为待确认，不自行寻找同名项目替代。
- 目录结构参考、内容参考和样式参考识别后运行样本蒸馏，只记录文件哈希、标题、段落、表格、图件和篇幅特征；不复制正文。

## 内容与载体分离

- “可以作为事实依据”控制材料内容能否支撑正文，不代表要把材料文件本身写入正文。
- 强制要求和项目事实的有效内容应转化为需求、约束、设计和验证描述，不应转化为“来自某文件”的编写过程说明。
- 内容参考中的通用方法、覆盖维度或技术解释可以重新核验和改写；历史项目的名称、数据、指标和结论不得继承。
- 文件名、资料编号、本地路径和资料目录只用于 Agent 取证与追踪，默认不对正式文档读者展示。
