# 提示词速查

写法：`提示词# 具体描述`（使用半角 `#`）。每次一个动作；下方编号仅为示例。

## 最常用流程

`需求# 想法` → `方案# IDEA-009` → `新任务# PLAN-007` → **在新聊天中** `执行#` → `测试#` → `任务完成#`

| 想做什么 | 提示词示例 | 作用 |
| --- | --- | --- |
| 记录新需求 | `需求# 增加用户同步功能` | 建立IDEA，不自动开发 |
| 补充已有需求 | `需求# IDEA-009 增加角色同步` | 更新指定需求 |
| 生成或修改方案 | `方案# IDEA-009` / `方案# PLAN-007 补充分页规则` | 编制Spec与修改方案，不编码 |
| 开新开发任务 | `新任务# PLAN-007` | 建任务、用短摘要接续新聊天并命名，等待下一动作 |
| 讨论任务细节 | `澄清# 确认分页结束条件` | 记录设计与需求结论，不改业务代码 |
| 开始实现 | `执行# 按当前方案实现` | 在当前任务中落地功能 |
| 验证功能 | `测试# 验证分页和异常处理` | 按指定范围验证并记录结果 |
| 正常结项 | `任务完成#` | 核验后登记成果、回传主任务、归档开发子任务 |
| 跳过未完成项结项 | `强制完成#` | 跳过未完成验证和规划功能，按实际交付收尾、回传与归档 |

**两种完成的区别：** `任务完成#` 默认要求验收满足；`强制完成#` 已明确授权跳过未完成项，无需再声明免验。未实现功能和未通过验证仍如实保留，不会变成“已实现/已通过”。也可指定对象，如 `强制完成# S03-T007`。

## 调研与知识

| 想做什么 | 提示词示例 | 作用 |
| --- | --- | --- |
| 分析项目结构 | `分析# /项目绝对路径 梳理模块和服务关系` | 只读分析并保存记录，无需先建任务 |
| 独立调研 | `调研# 比较两种分页方式` | 为当前任务创建调研子聊天 |
| 回传调研结论 | `调研反馈# 采用方案A，原因如下……` | 子聊天回传结论，主聊天更新原卡；不自动归档聊天或登记索引 |
| 完成并索引调研 | `调研完成#` | 回传最终调研结果，登记调研成果索引 |
| 保存任务经验 | `知识# 记录消息重投处理经验` | 保存到根目录知识库 |

## 记住这几点

- `任务#`、`【新任务】`、`【任务】`等同于`新任务#`；`知识记录#`等同于`知识#`。
- 新开发聊天默认使用 GPT-6.1 Sol、轻度推理，只带任务摘要，不复制全部历史；本轮可明确指定其他模型/推理强度，需完整历史时写“继承完整历史”。既有聊天复用原设置。
- 可以并行开多个任务；同一任务再次启动会复用已有聊天。
- 仅启动任务不会自动编码；需要立即实施可写 `新任务# PLAN-007，并立即实现`。
- 只有 `任务完成#`、`强制完成#`、`调研完成#` 会登记对应成果索引；未实现能力不登记。
- 归档保留聊天历史；开发子任务仍运行时先等其安全结束。无开发子任务时结束回复，不误归档主聊天。
- 普通提问、引用这些词或要求修改规则，不会触发业务动作。
