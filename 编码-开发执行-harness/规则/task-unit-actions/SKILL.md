# 任务动作与项目知识

## 根目录与任务入口

以引用本 Skill 的 harness 目录为根目录。知识根目录是该目录下的 `知识/`，与 `阶段/` 同级；业务代码或分析#指定的目标项目可以位于其他位置，不能把知识写入目标代码仓库或进程 cwd。

S03任务统一路径为 `阶段/S03-功能开发/S03-T编号-任务名称/任务.md`，任务单元目录直接位于阶段目录下，不创建中间的“任务”目录。新建、编号扫描、复用、恢复、完成回传及索引引用都按此规则定位。历史上下文引用旧层级时，按同一任务编号找到新目录并读取最新文件，不重建旧路径。S01/S02默认直接存放IDEA/PLAN；迁入项目的既有规划任务按原位置引用，不创建占位任务。

## 按需加载规则

先识别当前动作，再加载对应规则；已在当前有效上下文完整读取且文件未变的内容直接复用。不重复cat整份Skill，不批量读取references、所有项目文档或整个历史任务。上下文压缩后仅恢复本轮必需规则；不把“已读”缓存当作忽略新指令的理由。

默认先读任务frontmatter、任务恢复摘要和开发聊天接续区；无绑定任务的需求/方案/项目分析无需读无关任务。只有摘要缺范围、授权、版本或出现冲突时才逐层展开目标、功能点、设计、原卡及代码。仅接续不扫业务仓库；实施、验收和成果复用前仍核对当前代码及证据。

标准提示词使用“提示词# 描述”形式，完整提示词与半角 `#` 紧邻；`#` 后可直接接描述，也可加空格或换行。有效指令包括 `需求#`、`方案#`、`澄清#`、`执行#`、`测试#`、`调研#`、`知识#`、`知识记录#`、`分析#`、`新任务#`、`任务#`、`任务完成#`、`强制完成#`、`调研完成#`、`调研反馈#`。`【新任务】`、`【任务】`为任务启动的两个兼容别名，下文“新任务#”规则同样适用于这三个同义入口。

仅在用户将其作为本次明确行动指令时触发。普通提问、引用、示例、代码块、否定表达，以及讨论或修改这些触发词本身不触发业务动作。除明确支持的`【新任务】`、`【任务】`外，原括号形式、裸词“知识/知识记录”和冒号形式不作为触发别名。用户只提供触发词而没有描述时，按对应动作的上下文与对象规则处理；信息不足再询问，不编造范围。

示例：`需求# 支持业务结果批量导出`；`分析#/绝对路径/项目，梳理模块与服务关系`；`调研# 比较当前任务的两种数据交换方案`。这些是格式说明，不代表实际动作授权。

一次只执行一个动作；任务完成#与强制完成#包含完整收尾流程，维护已有任务、控制信息及功能索引；调研完成#更新原调研卡并登记导航索引；测试#复用单份测试记录并追加概要，其他动作按对应规则生成一张正文卡片。多动作或多主题批量请求先明确本次一个，不自动串行执行。普通补充、“继续”、Skill 名称本身不延续写入授权；用户明确要求修改已唯一定位的现有方案时，可按下述定向修订例外更新原卡。工具调用、内部消息、重试和恢复同一次触发不能重复建卡；用触发标识关联本轮产物。

任务动作及任务知识需有明确来源任务；缺少对象先询问，不猜测。分析#是项目级动作，可在尚无任务单元时直接使用，不为分析自动新建开发任务，也不受当前任务未完成限制；它不能切换活动任务或改变任务完成状态。

## 一次一卡与记录边界

- 澄清、执行、调研：触发后才创建对应任务子目录；三类新卡片及已有历史测试卡共用 `C0001-主题.md` 等递增编号，只扫描已经存在的目录及任务总览。未触发的目录不存在是正常状态。
- 任务知识：在根目录 `知识/任务分析/` 使用 `K0001-任务编号-主题.md`，K 编号在该目录全局递增，卡片标明来源任务和相关 C 卡片。
- 项目分析：在根目录 `知识/项目分析/` 使用 `P0001-项目名-分析主题.md`，P 编号在该目录全局递增，记录被分析项目的绝对路径及代码版本。
- 测试#不再新增C卡：测试方式和脚本持续维护，每次只向同一份 `测试/测试记录.md` 追加简短概要；具体见测试参考。
- 写入前检查冲突，不覆盖旧卡。除测试记录、完成动作控制信息及成果导航索引例外，一个新触发写一张卡；同一触发中断重试复用本轮已分配卡片，后续有效触发创建下一张并引用旧卡。
- 需求#明确补充已有 IDEA、方案#明确修改已有 PLAN 时更新指定原卡并保留变更说明，是新触发新卡的例外；未指定且存在多个可能对象时先明确对象。
- 用户明确要求对已唯一定位的现有方案作定向修订（如“把第1、3项补充到该方案”），也可更新原 PLAN 并记录版本与变更范围；仅评审、普通补充事实或“继续”不属于此例外，不授权新建卡片或实施代码。
- 调研启动及经用户授权的子会话反馈是专用例外：同一研究编号始终更新原调研卡，反馈不新增卡片。
- 不在任务下创建知识目录，也不复制根目录知识正文到任务中。任务.md 仅更新知识卡链接、状态及必要摘要。项目分析可在 `项目管理/项目上下文.md` 记录入口链接，不额外生成任务卡或索引卡。
- 卡片至少包含编号、动作、触发标识、时间、任务或项目来源、相关版本、输入依据、处理与结论、证据、未决项和建议。秘密值脱敏。
- 有效任务动作后同步任务恢复摘要及阶段/项目摘要；只更新实际变化，不复制历史全文。知识沉淀不改变需求、实现或验收状态；项目分析不自动替换已确认方案。普通聊天不改写记录。

## 动作边界

澄清只读检查与讨论，区分确认结论、假设和建议。执行完成已明确范围内的实际修改，保护无关变更，不自动转测试。测试只持久保存可复用方式、脚本、必要测试夹具和测试修改点，并在单份测试记录中摘要报告通过、失败、阻塞、未验证及覆盖范围；不默认保存完整输出、响应、实例调用记录或运行快照附件。不能把验证计划当作结果。缺少条件时说明阻塞，不编造成功。

需求或实现改变时在任务总览标记相关旧验证待复验并引用证据，不跨目录篡改历史卡。知识、分析和调研不自动授权代码修改、测试或下一动作。

## 新任务#、并行开发与独立完成确认

`新任务# 目标`（含任务#及两个指定括号别名）是任务建立与开发聊天摘要接续指令，不生成动作卡片。允许在其他任务未完成时启动、切换并行任务，无需先完成、暂缓或取消原任务。每个任务仍独立验收或由用户通过强制完成#豁免未完成项，并确认完成；新任务启动不代表旧任务完成。

新建开发聊天默认指定 `gpt-6.1-sol`、`low` 推理；用户明确指定其他设置时覆盖。复用已有聊天保持原模型。具体创建与记录方式见[开发任务分支与接续](references/开发任务分支与接续.md)。

标准按方案入口为 `新任务# PLAN-xxxx`，其中xxxx替换为已有方案的数字编号，例如 `新任务# PLAN-003`。仅给出编号即可定位方案并创建或复用一个开发任务，不要求再次描述方案内容。编号定位、默认范围及授权边界见[按PLAN编号启动任务](references/开发任务分支与接续.md#按plan启动)。

优先复用同目标待启动任务，否则以阶段内最大任务序号加一创建任务根目录。只使用本 Skill 的 [任务模板](assets/任务模板.md) 生成目标任务.md，填写已知目标、功能点与设计摘要，未知项标待确认；不创建任何动作子目录。小功能默认归属 S03，登记活动任务集合及本聊天绑定任务后按[开发任务分支与接续](references/开发任务分支与接续.md)创建摘要接续聊天（默认不继承历史），在新聊天按最小接续入口核对并等待动作指令。同一消息明确授权立即实施时，由新聊天在选定范围内承接；父聊天不并行实施。目标缺失先询问，不建无意义空任务。

`任务完成#`本身构成对当前范围的完成确认及回传归档授权，按[任务完成与归档](references/任务完成与归档.md)处理；普通任务完成#验收不足不自动结项；用户明确免验/裁剪范围的既有授权仍有效。`强制完成#`本身即授权跳过未完成验证和未实现规划功能，按真实交付强制结项，不再索取免验确认；详细边界见同一参考文件。普通自然语言完成确认不自动触发回传和归档。

用户确认当前任务完成时，普通模式核对当前版本验收，强制模式只核对对象、授权、实际产物和版本，不以未完成验证或功能为门槛；满足对应模式后更新控制信息中的确认表述、时间和状态，并按已确认的需求变化同步项目需求基线、记录 B 版本与依据；没有需求变化则记录无需更新。需求取舍仍有歧义时先明确，不把实现细节自动当作需求。普通模式验收未满足则列出缺口；强制模式将缺口保留为未完成/未验证并继续收尾，不修改失败证据。强制完成#本身即为用户完成确认，跳过未完成验证与规划功能不再二次确认；不自动新建后续任务。完成确认不自动启动下一任务；同一消息明确确认完成并给出新任务#时可依次处理，但仍不自动执行。

回复给出实际结果与本次卡片链接；测试回复链接到测试方式/脚本及单份测试记录的本次概要。普通对话不伪装成已完成动作；主会话接收调研反馈仅更新原卡并建议下一步，等待用户触发澄清#或执行#。

新任务#建立时只引用适用的需求基线编号及版本；新需求作为候选变化记录，不自动更改基线。首次基线可在澄清#中依据用户明确确认的需求建立，具体版本与同步规则见进度参考。恢复摘要和基线均属控制信息，不新增提示词或动作卡片。

生成任务时，以目标任务文件所在目录重新计算模板内所有相对链接，尤其是指向 harness 根目录项目管理/需求基线.md 的链接；不要原样复制模板中的相对路径。写入后检查链接目标存在，不为适配链接移动项目文件或创建重复基线。模板是 Skill 的输出资源，不是已启动任务。

## 需求#、方案# 与开发任务的关联

涉及需求收集或方案编制时读取 [随手收集与后续关联](references/进度与阶段.md#随手收集与后续关联)。初次收集或生成方案需用户显式输入对应提示词；已有方案定向修订遵循上述例外，引用、示例、否定或普通讨论不触发。目录只决定存放位置，打开目录不会自动记录。

需求#一次收集一张 IDEA 卡片，直接放在 S01 阶段目录；方案#一次形成或更新一张 PLAN 卡片，直接放在 S02 阶段目录。不得在这两个阶段下另建“需求”“方案”子目录，也不为收集建立汇总正文文件。文件仅在真实触发时创建。

这两个是阶段级动作，无活动任务也可使用；可在当前任务进行时记录需求或编制方案，但不创建或切换最小任务单元、不修改业务代码、不改变当前任务范围与完成状态。需要启动另一任务时通过新任务#，允许并行，不以其他任务完成为前置条件。

新任务#可指定 IDEA 或 PLAN，目标任务.md 中记录来源链接和选定功能范围，并回填原卡的关联任务链接。只建立本次选定的一个任务；方案中的拆分建议不自动变为任务目录。正文只保留在来源卡，关联信息属于控制信息，不算额外一张卡。

## 发布动作扩展

`发布# [目标]`为独立发布动作，执行前读取[服务发布](references/服务发布.md)，定位目标任务和项目已确认发布契约；没有可用契约先补齐关键参数，不生成可直接执行的虚假默认值。该扩展优先于旧动作枚举；不默认创建新任务，不自动执行数据库迁移或完成业务任务。仅讨论本指令不触发发布。
