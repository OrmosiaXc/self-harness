# 规则维护与事实同步

仅在用户要求维护规则、重新梳理 harness，或发现恢复信息冲突时读取。本规则不要求每轮扫描全目录。

## 适用范围与授权

- 明确的本轮维护请求可直接修改对应规则和必要的摘要；普通讨论不自动写入。长期维护需求（如 IDEA-010）说明维护目标，不构成无限期、无限范围的修改授权。
- 用户最新明确指令优先；同一任务内，以有来源和日期的最新已确认需求变更解释旧方案。草稿、建议及文件更新时间本身不构成用户确认。冲突无充分依据时保留差异并澄清，不擅自选择。
- 可复用的流程约束放入规则；业务选择保留在 IDEA、PLAN 或任务中。例如调度方式、日志粒度、认证代理方案不能仅因一个任务采用就推广为全局标准。
- 维护本地规则副本时，同步其入口及受影响模板；不自动覆盖用户全局 Skill，不创建业务动作卡，不代触发完成或成果登记。

## 恢复与证据

- 恢复先读 frontmatter、恢复摘要和接续区；摘要与后文最新决定冲突时，只展开相关记录并校正摘要，保留原决定及日期。旧规划功能表不应覆盖新决定，也不能据此推断全部功能已经实现。
- 区分“用户确认的需求”“任务文档记载的实现”“当前代码核实”“指定版本的运行验证”。文档复核只能声明前两类，不能把历史验证迁移为当前通过。
- 旧文件可能使用中文元数据键或“开发中”等状态；按实际含义读取，汇总时可将开发中归入进行中，不为格式统一擅改任务状态或 R/I 版本。
- 聊天标识、host 和归档状态须有实际工具结果支持。目录文档中的名称或混合字段不能替代有效标识，未知时记录未核实。

## 汇总与并行协调

- 改动进度前重读最新相关记录。按真实任务.md去重统计有效任务，IDEA、PLAN、动作卡及聊天不计任务；迁入项目真实存在的S01/S02规划任务纳入项目计数，S03采用直放目录。
- 完成数只依据已有完成确认，不把代码已写、测试被豁免或本次文档整理自行解释为完成。当前摘要与历史记录分开，历史时点的旧计数不批量替换。
- 多任务并行时，项目总览列出活动集合，以各聊天绑定确定当前任务，不让一个已归档任务成为所有聊天的当前任务。
- 共享同一文件即记录协作关系；不同方法也不等于无冲突。写前核对最新差异，保留另一任务改动，按实际影响决定回归范围。
- 仅解析验证须明确隔离边界；调用 Controller 前检查其是否写库、发消息或上传文件。Mock 通过只说明模拟契约，不代表上游真实协议或端到端业务通过。

## 维护收尾

检查改动入口、相对链接、汇总计数及规则示例一致性；记录本次检查范围与限制。不得因维护而新增成果索引、关闭任务、归档聊天或更新需求基线版本。QA 按项目按需记录规则执行。
