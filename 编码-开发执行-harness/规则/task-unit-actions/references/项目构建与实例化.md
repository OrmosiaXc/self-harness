# 项目构建：新项目 Harness 实例化

## 触发与边界

`项目构建# [项目名称] [目标项目目录] [模板目录] [关联代码目录及要求]`：根据指定或当前模板，在目标项目下生成可供后续开发使用的harness实例。这里的“构建”是开发治理初始化，不是编译、打包、部署或创建业务代码工程。

这是项目级动作，无需来源任务；一次一卡、任务来源必需、只建任务.md等开发任务规则不适用本动作。允许一次生成构建所必需的多个规则、上下文和入口文件。不创建IDEA、PLAN、S03业务任务、新聊天或成果索引，不自动执行下一业务动作。

用户给定目标与模板后，仍须完成下述项目基础输入确认；已经明确确认的项目不重复询问。仅引用、讨论、否定或代码示例不触发。缺少目标目录且上下文不能唯一定位时先询问；项目名可从目标目录推定。模板默认使用当前引用本skill的harness，实例默认命名为“项目名开发-harness”；实例作为来源时排除该实例业务记录，仅提取规则和空结构，不传播原项目事实。

## 构建前项目基础输入确认（必需）

开始复制、创建或修改实例前，必须向用户集中确认以下五类输入及用途；已有明确回答直接复用，只询问缺项。不从当前cwd、目录扫描结果或历史建议推定用户已选定实施工程。

| 输入 | 必须确认的内容 | 允许的空缺状态 |
| --- | --- | --- |
| 基础实现后端 | 实际项目绝对路径；多仓时分别说明职责 | 尚未构建，暂不填写 |
| Python算法后端 | 是否存在独立算法项目；若有提供绝对路径及与业务后端的关系 | 不涉及 / 尚未构建，暂不填写 |
| 前端实现项目 | 实际生产候选前端路径；原型另行标注 | 尚未构建，暂不填写 |
| 项目相关资料 | 需求、合同、设计、接口、数据样例、验收等资料文件或目录位置 | 暂无 / 待提供 |
| 历史项目参考资料 | 是否有历史工程、原型、文档或截图；若有提供位置及参考用途 | 无历史参考 / 待提供 |

可用一条问题请用户逐项回复“路径 / 尚未构建 / 不涉及 / 暂无 / 待提供”。空白不等于确认不存在：用户明确表示尚未构建或允许暂缺后即可继续，不因没有基础底座强制阻塞。用户仅回答部分时，未确认类别继续等待确认，可先做不产生写入的材料定位；不可跳过前置确认开始构建。确认只确定定位与分析范围，不自动批准建议架构或业务规则。

## 工程分析、资料归档与索引（构建必需产物）

本节是项目构建动作的一部分，无需另行触发分析#。仅分析已确认的位置；不可访问或资料缺失时明确记录原因、影响和补齐入口，不伪造分析。

- **实施工程分析**：分别梳理基础后端、Python算法后端、前端的目录结构、技术栈证据、模块职责、入口、配置与依赖、接口及调用关系、运行与验证方式、已有能力和差距。Python额外核对算法入口、输入输出、模型/资源依赖及服务调用边界；前端区分原型、模拟数据与真实API。分析跨工程契约和依赖关系，未核实部分单列。
- **资料整理**：登记需求、合同、设计、接口、数据样例、验收资料及其版本/日期、来源、确认状态和适用范围；整理可检索的摘要、关键约束、需求线索、冲突及待确认项。历史资料单列适用边界，不提升为当前需求或实施依据。
- **正文归档**：工程分析保存到`知识/项目分析/`，沿用该目录P编号规范；资料摘要及来源说明保存到`资料/项目资料/`和`资料/历史参考/`。不存在的工程写入上下文缺项登记，不生成空洞分析正文。业务代码、依赖、构建产物、数据库、模型权重和敏感配置不复制进harness。普通资料默认归档整理后的正文与原件引用；用户要求复制原件时仅复制所需可读资料，保留原名、来源和版本，避免同一正文多处维护。不可读格式标记待解析，不仅凭文件名下结论。
- **导航索引**：建立`索引/工程与资料/README.md`，逐条链接工程分析、资料摘要及按需归档的原件；记录来源绝对路径或用户提供的链接、分类、用途、版本/核实日期、分析或解析状态与限制。该索引为初始化资料导航，独立于任务完成结果和调研结果，不受完成类动作才能登记成果索引的限制，不表示业务交付完成。
- **闭环关联**：在项目上下文中记录五类输入的用户确认结果、缺项状态和确认依据，链接统一导航；目录业务定义说明新增资料目录及索引职责；实例README提供导航入口。构建继承清单列出这些新产物及其来源。更新已有实例时增量维护、保留版本来源，不重复复制、不覆盖用户整理结果。
- **核验**：检查已确认的每个工程与资料来源都有分析/整理结果或明确阻塞说明；索引可定位正文及来源；缺失工程均有用户允许暂缺的记录。证据仍区分静态分析与实际运行，不自动构建、启动或连接外部系统。

## 执行步骤

1. **核对输入及现状**：先完成五类基础输入的用户确认，再按本节执行。读取适用AGENTS、模板README、规则入口与必要初始化文件；检查目标是否已有harness或AGENTS。检索项目材料、README、依赖清单、目录、启动脚本及相关代码入口，优先用rg定位，按需读取。不要遍历依赖、输出敏感配置或默认联网。目标不得等于模板或位于模板内部，避免自复制。
2. **辨别工程身份**：依上文“工程分析、资料归档与索引”完成已确认工程与资料的同步分析、整理、归档和导航。登记真实绝对路径、源码/原型/历史归档/生产候选/技术方案/截图等职责。区分现状、已确认要求、评审建议和待决策项；多套技术栈并存时不得仅凭目录名决定实施主工程。没有证据的架构、容量、流程规则标为待确认。
3. **继承完整规则**：保留模板AGENTS、动作skill及所有references、assets、agents元数据、编码规范、阶段说明、提示词说明和索引约定。排除.DS_Store、依赖、构建输出及原项目任务、知识正文、已完成索引和秘密。不能省略未读规则文件；完整复制不等于要求每次加载全文。源模板保持不变。
4. **填写实例上下文**：明确目标、用户、业务范围、harness根目录、关联仓库职责、技术栈证据、版本核实日期、运行/验证入口及前提、共享文件与外部依赖、待确认项。运行命令来源于项目文件，只作静态登记并标“未执行”，不以登记命令视为验证通过；识别带--write、数据库重建、容器及发布副作用的入口。
5. **形成项目规则**：生成“项目管理/目录业务定义与执行方式.md”，解释材料和代码目录、阶段及卡片职责、动作触发、唯一正文、开发顺序、恢复方式、验证、完成和发布边界。按项目实际增加规则/<项目skill名>/SKILL.md及必要参考，写合法name/description，通过AGENTS和skill入口可发现。核心技能随实例携带；宿主外部能力按需引用，未安装不得宣称可用，不自动安装插件或改全局技能。
6. **接入入口**：在实例AGENTS与README关联项目上下文、执行说明和项目skill。目标根无AGENTS时创建简短路由；已有时保留全部既有规则并增量补充去重，不覆盖。关联代码仓库只登记，不为初始化擅自改其代码或指令。聊天、模型、消息、worktree和子代理能力依宿主约束，模板默认不能越过授权。
7. **初始化控制状态**：首次初始化保持需求B0、有效业务任务0/0，不把材料记载自动提升为本轮确认，不把规则维护算业务进度。阶段和知识/索引目录按模板准备，动作子目录仅实际触发后生成。重入现有实例则保留已有基线、任务、知识、索引、进度与版本，绝不重置为B0或0/0。
8. **记录继承与验证**：生成项目管理/模板继承清单.md，登记源路径、时间、模板文件相对路径及SHA-256、原样继承/实例化调整/排除与理由，独立列出新增文件。检查模板规则完整性、相对链接、技能frontmatter及初始化残留；模板资源中的占位符可保留，实例上下文中的未知内容明确待确认。只报告实际静态检查，不启动服务、构建、迁移、测试或发布。

## 已存在目标与中断恢复

写前检查目标及未提交改动，默认复用匹配的实例，不另建重复实例。不覆盖用户内容；能增量合并的入口、说明和技能在重读后合并，有冲突先保留原文件并说明差异，确实影响规则选择再向用户确认。以当前文件及继承清单识别已完成步骤，中断重试继续补齐，不复制旧业务记录、不重复添加入口。模板升级与实例更新分别明确范围，不能借实例化覆盖全局配置。

## 交付

给出实例README、项目上下文、目录执行说明、项目skill、工程与资料导航和根AGENTS的可点击入口，说明继承范围、实际校验、待确认条件及下一条可用动作。初始化本身无需另建业务完成卡或更新成果索引。用户后续通过需求#、分析#等进入业务工作；本动作中的流程示例不构成执行授权。

示例：`项目构建# 示例项目，目标目录 /项目目录，模板 /模板目录，关联后端 /代码目录；区分原型和正式工程，完整继承规则与项目技能。`
