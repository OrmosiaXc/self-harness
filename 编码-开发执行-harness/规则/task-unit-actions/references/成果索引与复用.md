# 成果索引与复用

## 位置与边界

S03来源任务路径统一为 `阶段/S03-功能开发/S03-T编号-任务名称/任务.md`，其执行、测试等记录相对该任务单元定位。用户明确要求目录迁移时，可以只修复既有索引的路径和链接；这属于导航维护，不注册新成果、不改变完成状态、版本或验证结论，仍不得借此补录成果。

harness根目录新增 `索引/任务完成结果/` 和 `索引/调研结果/`，与阶段、知识同级。索引存放短摘要、可检索关键词、复用契约及原文/代码链接，不复制方案、测试输出、调研报告或源代码。它是完成动作的导航附属产物，不计为第二张正文动作卡，不改变知识目录规则。

只有用户将 `任务完成#`、`强制完成#` 或 `调研完成#` 作为实际动作指令触发后，才允许注册、创建或更新对应成果索引。任务完成#登记验收范围内已完成的功能点；强制完成#仅登记实际已交付的能力并标明未验证/失败边界，未实现项不注册，无可复用交付时索引不适用；调研完成#登记主会话已接收的调研结论。

初始化目录、维护Skill、普通完成表述、历史任务已完成、代码已实现、测试通过、调研反馈#、需求#、方案#、新任务#、执行#、测试#均不构成索引写入授权，不自动补录历史成果或创建复用候选条目。无完成触发时只能只读检索和在当前合法任务记录中注明复用线索，不写索引。目录与README规则维护不属于成果注册。

同一次有效完成动作的主会话接收、失败重试和中断恢复可以继续写入，但必须核对原始用户触发、对象及收尾标识/反馈版本，不能将其用于新增其他成果或后续新版本。历史已完成成果若要首次注册，需用户明确对该对象触发相应完成动作；不自动将过去的完成记录追溯为本轮批量建索引授权。

## 任务功能索引

按可独立调用/复用的功能点建条目，稳定文件名建议 `任务编号-F01-功能名称.md`。F编号在原任务内递增分配，已有功能点编号可直接沿用；同功能不同版本更新原条目并留简短修订依据，不按每次触发重复建文件。

每条至少包含：

- 稳定索引ID、标题、关键词（业务词和技术词）、更新时间、状态、来源触发/收尾标识。
- 完成范围与排除项、用户确认依据；未确认写明，不把任务状态扩展到所有场景。
- 来源任务、IDEA/PLAN及实际采用的Spec版本、实现变更记录链接；无适用项如实写无。
- 实际仓库绝对路径、分支/提交、R/I版本、相关未提交改动；关键源码可记录摘要辅助发现漂移。
- 每项能力的真实包名、类名、方法签名、源码链接及已有调用示例；不能把方案中的拟建类当成实现。
- 输入输出、配置前提、资源生命周期、异常和调用方责任的最小复用契约。
- 验证证据链接、对应版本/日期/环境/通过范围、未覆盖场景；历史版本测试不能直接证明当前版本通过。
- 适用业务场景、复用建议与待验证条件；复用其他索引时用链接关联，不复制正文。

收尾执行者在完成登记后、回传前写索引，并在原任务“完成回传与归档”保存索引链接/状态。主会话接收时核对链接、源码符号与验证依据，索引未写成功则保持“待补索引”，不归档子会话；重试只补缺失步骤。无主会话的任务由当前执行者登记。只有索引要求缺失时，不回滚已成立的业务完成状态。

## 调研索引

文件名建议 `研究编号-主题.md`，研究编号沿用来源任务与调研卡编号。包含稳定ID、标题/关键词、更新时间、研究日期/反馈版本、研究问题、简短结论、原调研卡链接、关键外部来源、适用产品/版本/条件、未决点、相关任务或功能索引、用户调研完成#依据及主会话回执。

状态采用“已完成调研/需复核/已被替代”，结论明确区分事实、推断和建议；调研完成不代表功能已实现或测试通过。没有代码时写“无代码实现”，禁止编造方法链接。时效性强的结论必须在复用时重新核查，按原文日期/适用版本判断，不能把过期调研当作当前事实。

调研完成#的索引由接收主会话在原调研卡落盘成功后写入，子会话不并发写共享索引。无匹配研究编号、未返回报告或缺少关键结论依据时不登记已完成条目；证据不足的结论可以作为明确局限的已完成调研结果，但不得表述为已证实。

## 后续需求与开发的必经检索

需求#、方案#、新任务#及执行#遇到新增/扩展功能时，先按业务词、技术词、服务名检索两类索引，再决定复用方案。

1. 需求#仅轻量查找相关条目并在IDEA记录候选引用及待核对项，不扩展为全仓分析或自动生成方案。
2. 方案#、新任务#与执行#打开命中条目的原任务、方案和实际代码，核对当前方法签名、配置、依赖与对应测试范围。记录“直接复用/适配后复用/不适用”和依据；调用现成统一服务，避免重复写SDK封装或消息基础服务。
3. 索引未命中时，继续查相关代码与既有任务后再认定能力缺失；没有索引不等于没有实现。
4. 条目指向旧提交、未提交文件已变、源码缺失、接口改变或测试版本不匹配时，作为待复核线索，不承诺兼容。在当前已授权文档/任务记录中注明差异并提示索引可能过期；执行#或测试#不更新索引，待用户再次触发对应完成动作后核对并更新，保留旧验证范围。
5. 确需新增底层实现时说明原能力不能满足的具体缺口，而不是因旧任务已归档重写。优先最小适配，新增场景的业务验收仍独立进行。

例如数据集产品推送先查“S3/对象存储/上传”和“Pulsar/消息/推送”，再核对实际ObjectStorageService与PulsarService及验证边界；产品元数据、消息载荷、业务幂等和存储成功后发送等编排由新需求明确，不能从已有工具自动推导为已实现。

## 幂等、并行与失败

索引写入先查来源任务/研究编号＋功能ID。同一收尾标识/反馈版本不重复登记；低版本不覆盖高版本。写前读取最新文件，更新本条目，不覆盖其他任务条目。不要建立需要每次手工复制的汇总正文。

任务重开、废弃或替代时先在原任务记录状态，索引只读；下一次对应完成动作处理索引时保留历史指向，标待复核或已被替代并链接后继。文件路径和符号链接交付前核验，秘密凭据不入索引。写入失败必须保存原成果及待补状态，说明未完成步骤，不声称索引已可用，也不因此新建替代聊天。
