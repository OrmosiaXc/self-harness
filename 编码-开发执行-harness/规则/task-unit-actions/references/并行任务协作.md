# 并行任务协作

## 启动与完成

允许多个最小任务单元同时进行，并在不同开发聊天执行、测试和修订。新任务#及其别名不再要求前一个任务完成，也不要求为启动新任务暂停旧任务。一次启动只创建或复用一个任务并以最小摘要接续一个聊天；同一任务已有聊天则复用。

每个任务独立维护范围、R/I版本、验收与用户完成确认。另一个任务完成或新聊天创建成功不能代替本任务验收。阶段完成仍要求纳入范围的有效任务完成，不能因并行规则把未完成任务标已完成。

## 任务定位

“当前任务”指当前聊天绑定的任务，不再是全项目唯一执行资格。解析动作对象依次使用用户明确任务编号、当前聊天绑定任务、唯一可确定的上下文；仍有多个候选时才询问，不能凭其他聊天最后写入的项目指针选目标。

项目进度维护活动任务集合（任务编号、状态、聊天ID/入口、范围及依赖）；阶段进度维护所有任务行。旧“当前任务”字段仅表示最近关注任务，不覆盖其他活动任务。未启动候选保留待启动，不自动标进行中。更新仅限本任务行和汇总计数，先重新读取文件、合并其他聊天最新变更，禁止用旧快照覆盖整个进度文件。需求基线的编号和版本变更也需重新读取后串行落盘。

## 代码与共享文件

各任务登记修改范围、依赖和代码工作目录。不同文件可并行修改；同一文件或公共接口可能重叠时先核对其他任务当前改动，拆分修改边界并协调写入顺序。文件存在不表示需要独占整个模块；只有实质冲突部分等待，独立部分继续。

摘要新聊天不复制历史，也不自动隔离业务仓库；完整历史fork同样不隔离共享代码。实际cwd/权限以宿主结果为准。父聊天负责交接与管理，同一任务交接后由其开发聊天修改业务代码；其他聊天可同时推进各自任务。不得删除、回滚或提交其他任务的改动。需要隔离时可采用宿主支持的独立worktree/checkout，并记录路径与集成方式；不为形式上的隔离移动共享仓库或自动合并。

测试与构建记录实际提交、相关未提交变更和测试对象，识别其他任务引起的失败；不得把全仓成功/失败未经分析全部归入本任务。合并或共享改动后，针对受影响契约复验。任务依赖按接口/数据就绪条件管理，不把所有任务统一排队。

## 聊天、授权和恢复

每个开发聊天登记任务与来源方案，只执行其授权范围，不重复fork。允许并行不等于自动开启所有方案工作包，也不等于授权自动spawn内部Agent、发布或合并。用户明确启动并要求实现的任务可按该授权继续，无需因其他任务未完成再次求确认。

恢复时读取绑定任务的摘要和实际代码，保留其他任务状态。因旧串行门槛留下的“等待前任务完成/暂缓才能启动”提示作废，改为按本任务实际环境与权限决定能否推进。
