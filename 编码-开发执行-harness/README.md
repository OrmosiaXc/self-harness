# 编码开发 Harness 使用说明

这个目录用来管理软件开发过程中的需求、方案、任务、测试和经验。业务代码仍放在自己的项目仓库中；本目录保存项目背景、任务记录和使用规则。

## 目录是做什么的

| 目录 | 用途 | 什么时候会有内容 |
|---|---|---|
| `项目管理/` | 保存项目仓库位置、运行方式、当前进度和已确认需求。 | 开始使用时先填写“项目上下文”。 |
| `阶段/S01-需求与范围/` | 保存需求卡，记录“想做什么、为什么做、范围是什么”。 | 使用“需求#”后。 |
| `阶段/S02-方案与设计/` | 保存方案卡，说明具体怎么改、验收标准是什么。 | 使用“方案#”后。 |
| `阶段/S03-功能开发/` | 保存开发任务及其澄清、实施、测试和收尾记录。 | 使用“新任务#”后。 |
| `规则/` | Harness 的动作规则和编码规范。一般由 Agent 按任务读取。 | 通常无需手动修改。 |
| `知识/项目分析/` | 保存对项目结构、模块和调用关系的分析。 | 使用“分析#”后。 |
| `知识/任务分析/` | 保存可复用的开发经验。 | 使用“知识#”后。 |
| `索引/任务完成结果/` | 查找已完成任务的结论、代码位置和验证范围。 | 任务完成后按规则登记。 |
| `索引/调研结果/` | 查找已完成调研的结论和适用范围。 | 调研完成后按规则登记。 |

## 开始使用

1. 在支持项目指令和文件操作的智能开发工具中打开本 Harness 所在目录。
2. 填写 [`项目管理/项目上下文.md`](项目管理/项目上下文.md)：项目代码在哪里、怎么启动/验证、需要遵守哪些项目规则。不要把密码或 Token 写进去。
3. 查看当前进度：[`项目管理/项目进度.md`](项目管理/项目进度.md)。
4. 按下表向 Agent 发送提示词。`#` 使用半角符号；示例中的编号由 Agent 按项目记录分配。

## 提示词和使用案例

| 想做什么 | 提示词 | 使用案例 |
|---|---|---|
| 记录一个新想法 | `需求# 描述` | `需求# 增加用户批量导入功能，支持 CSV 文件并提示错误行` |
| 修改已有需求 | `需求# IDEA-编号 描述` | `需求# IDEA-001 补充：导入时需要校验用户邮箱唯一` |
| 为需求编写方案 | `方案# IDEA-编号` | `方案# IDEA-001` |
| 修改已有方案 | `方案# PLAN-编号 修改内容` | `方案# PLAN-001 补充重复邮箱时的处理规则` |
| 创建开发任务 | `新任务# PLAN-编号` | `新任务# PLAN-001` |
| 讨论需求或方案细节 | `澄清# 问题` | `澄清# CSV 中存在重复邮箱时，是整批失败还是只跳过重复行？` |
| 按方案实际改代码 | `执行# 实施要求` | `执行# 按 PLAN-001 实现 CSV 用户导入` |
| 验证本次修改 | `测试# 验证范围` | `测试# 验证正常导入、重复邮箱和格式错误行，并记录结果` |
| 正常完成任务 | `任务完成#` | `任务完成# S03-T001` |
| 有未完成项但要求按现状收尾 | `强制完成# 任务及未完成情况` | `强制完成# S03-T001 当前实现已交付，异常路径测试未完成，请如实登记` |
| 只读分析项目结构 | `分析# 项目路径 分析目标` | `分析# /Users/me/project 梳理服务模块及调用关系` |
| 发起专项调研 | `调研# 调研问题` | `调研# 比较当前项目适用的两种消息重试方案` |
| 将调研结论反馈给主任务 | `调研反馈# 结论` | `调研反馈# 建议采用指数退避，原因是……` |
| 完成调研并登记结果 | `调研完成#` | `调研完成#` |
| 沉淀开发经验 | `知识# 经验主题和内容` | `知识# 记录批量导入任务中的幂等处理经验` |
| 按项目要求发布服务 | `发布# 目标` | `发布# 测试环境用户服务` |

### 常用开发顺序

```text
需求# → 方案# → 新任务# → 执行# → 测试# → 任务完成#
```

小改动可直接从“新任务#”开始。创建任务不会自动修改代码；要开始实现时再发“执行#”。如果只想先讨论方案，用“澄清#”，不会修改代码。

## 任务记录放在哪里

创建任务后，打开 `阶段/S03-功能开发/` 下对应的 `S03-T编号-名称/`：

```text
任务.md       任务目标、范围、验收要求和当前状态
澄清/         需求或方案问题的讨论记录
执行/         实际修改内容和实现记录
测试/         测试方法及结果摘要
调研/         与任务有关的专项调研
```

子目录会在需要时创建，不必提前建立。任务正文放在任务目录；经验正文放在 `知识/`，任务里只保留链接。

## 查看规则

- 项目背景填写在 [`项目管理/项目上下文.md`](项目管理/项目上下文.md)。
- 当前任务和阶段查看 [`项目管理/项目进度.md`](项目管理/项目进度.md)。
- 可用提示词的详细规则见 [`提示词速查.md`](提示词速查.md) 和 [`AGENTS.md`](AGENTS.md)。
- Agent 执行具体动作时会按需读取 `规则/task-unit-actions/` 中的细则；编码时会读取 `规则/code-skill-self/`。
