# 文档编写规范

本文件是样式与共性写法唯一入口。用户最新明确要求、正式项目模板及确认目录优先；历史样本只能供比较，不能覆盖本项目规则。新建/恢复任务须读当前有效版本，不复制旧提示词参数。

## 跨项目复用：现有Word修订与格式一致性

新项目只继承流程和规范，不继承来源项目身份、目录、业务编号、用例数量、环境、阈值或执行结论。用户最新要求及正式模板优先；原稿实际格式优先于下方建议基线。

- 已有Word采用定向补充与修订模式，以最新权威Word及哈希为基准，保留原稿和用户修改；按指定范围调整，不强制重新列整篇大纲、拆成逐章MD或重写整稿。新文档仍按大纲确认流程处理。
- 填表继承目标表同类单元格的字体（含中西文）、字号、字重、对齐、缩进、行距、段距、边框底纹、边距、列宽、合并及行高策略；新增行不误用表头格式。章节继承前后同级标题和正文的实际格式，核对直接格式覆盖而非只看样式名。
- 同类表总宽一致并匹配所在节正文可用宽度；合理分配列宽。易被长编号撑宽的表采用固定布局，同步网格与单元格宽度，按字段分段换行且保留完整编号字符。不任意缩小字号，不嵌套表格。
- 无专用要求时可采用表头宋体五号、加粗居中、灰底，内容水平居左及垂直居中、实线边框的建议方案；新项目须在项目格式配置确认，不能覆盖原稿或正式模板。
- 题注沿用原文档题注样式及自动编号域，不手写固定图表号；检查编号顺序、图表目录和引用。表题注、表头及第一数据行同页，跨页重复全部表头行，不把整张长表强行绑定在一页。
- 复核图文、分页、裁切、溢出和异常留白；结构核对、替代字体渲染和原生Word/WPS验证分别记录，预览通过不等于原生排版已验证，设置域不等于目录实际刷新。

## 跨项目复用：模板表达、测试追溯与版本联动

- 同时继承指定模板同类章节的组织方式、语气及深度，内容回到当前项目取证；平行章节结构与结论保持对应，不搬用旧项目事实。
- 正式引用使用《文档名称》及核对后的实际章节、表名；内部调度编号和路径留在任务记录，不混入正文。覆盖表配套对象、链路、范围、依据、统计及结果边界说明，避免只有表格或追溯话语。
- 测试项、独立用例、步骤、执行次数分别统计。共享用例按完整用例编号去重，分项与总计一致，执行率/通过率注明分子分母。用例按任务场景及风险组织，不默认固定每项用例比例或总量。
- 大纲测试项→细则用例/步骤→执行记录/证据/问题→报告统计与结论保持关联。展示精简关联编号时保留资料中的完整多对多关系，不任意截断或重排业务编号。
- 实际结果与步骤逐项对应，是否通过、优先级和结果各自核对。用户确认、静态资料、运行证据及验收批准区分；只勾选通过不自动生成结果，不把旧执行确认扩大到新增或变更用例。
- 模板中的性能数值、资源阈值、无积压或零缺陷不直接套用。正常链路与异常注入、重试、降级、告警的验证边界按实际用例说明，缺少专项证据不得写成已验证。
- 上游文档变更后重新核对编号、数量、步骤和结果，列明受影响表格、追踪关系、统计及结论。只在授权范围内修订，不自动改写其他文档。
- 最新Word保持一个固定成果入口；共用Markdown保持唯一正文。索引登记当前版本、来源、SHA-256、适用范围、关联文档及缺口，历史保留替代关系。后续复用先查索引再读取原文，不凭修改时间或聊天旧摘要判断当前版本。
- 用户指定归档依据原件时复制只读副本，核对来源/副本哈希并登记路径；默认仅登记来源，不批量复制仓库或临时锁文件。完成收尾同步成果、共用资料引用、知识和进度，未验证与遗留项不因归档而消失。

## 项目格式配置

状态：待新项目初始化确认。下表为可采用的建议基线，不是其他项目合同或强制标准；有正式模板时逐项读取并替换。首次确认后记STYLE版本，后续变更明确旧条款失效，避免同时维护矛盾规则。

| 元素 | 建议基线 | 项目确认值/来源 |
|---|---|---|
| 页面 | A4纵向，上下25.4mm、左右31.8mm；宽表可用横向节并说明 | |
| 正文 | 宋体小四12pt，固定21pt，两端对齐，首行2字符，段前后0 | |
| 标题 | 各级12pt加粗、无缩进，连续编号；保持真实Heading | |
| 目录标题 | 宋体四号14pt加粗居中 | |
| 目录条目 | 三级12pt，逐级缩进0/2/4字符，固定21pt；不继承标题加粗 | |
| 表格 | 表头10.5pt加粗、表内9pt；宋体，跨页重复表头，不固定行高裁字 | |
| 图表题注 | 10.5pt居中，表题上、图题下 | |
| 封面及标识 | 标题16pt加粗，其他字段按项目模板；未知身份不编造 | |
| 页眉页脚 | 宋体9pt，页码策略按模板确认并分节检查 | |
| 代码块 | 单独块且可复制、保留语法与缩进；边框/浅底区分，字体按项目确认 | |

确认值包括中西文字体及直接格式、21pt是否适用、段落缩进、TOC级数、页码起始、表格列对齐/边框/内边距、图宽及封面布局。图表上限取节实际正文宽度，不硬编码图宽或缩小字号凑版。字体缺失、目录未刷新、渲染不可用分别记录；设置域不等于实际更新页码。

## 结构与版本

章节来自用户最新目录或原始文件要求；技术设计才采用专项核心结构，报告手册台账按定位组织。标题编号由一处生成，MD字面章号与Word自动编号不能重复。新文档通常每个一级章一个MD源，前置页单独维护；现有Word定向修订不强制拆章；R/O/C/D为内部追踪，F/STYLE为共用事实与格式版本。格式修订不暗改业务内容。

已有Word修订先吸收用户差异，具体见定向修订技能。全稿比较前后章/段/表/图/附件及关键字段，渲染最终版本逐页核对裁切、孤立标题、图题、跨页、留白、代码和目录实际显示。其他文档的例外不当作全套标准。

## 共性写作与交付要求

### 小节内容与总分总

叙述性子章节采用“总—分—总”：开头交代目标、适用对象和边界；中间说明机制、流程、具体措施、依据及图表；末尾用简短段落收束判据、输出或后续处置。避免只有表格和一句说明、表格结束后直接进入下一小节。总结应回应本节业务内容，不机械添加“综上所述”或重复表格。台账单条、术语和简单字段不强制扩写，不设统一字数或页数指标。

### 可执行步骤、验证与回退

仅方案、手册和实施操作类文档中确需指导执行的子章节按“步骤1、步骤2……”顺序展开，步骤标题加粗，但不因此自动纳入目录。写清前提与执行角色、输入与配置、具体动作、预期结果或判据、留存证据、失败停点与后续处置。实际可执行部分应给出与项目吻合的命令、SQL或脚本正文及参数解释，不能只写“执行检查”“验证正常”或一个脚本路径。命令和完整交付脚本保持一致；未确认参数明确待填写，不虚构环境、凭据或成功输出。

回退不止一句“恢复备份”：按适用范围展开触发条件、停止新增写入/任务、现场状态保全、数据库与文件/对象处理、应用版本与配置恢复、消息及任务状态处置、业务核验和重新开放。解释动作顺序、依赖、可逆边界及失败分支。复用已完成迁移回退方案时核对适用性，不将清库、重启或重新运行当作通用恢复方式。编写命令或脚本不代表已授权在实际环境执行。

### 流程与统计图表

迁移、上线、回退、集成实施及关键检查等执行类内容应配套适用的流程图；总结说明类按成果解释需要选图，不机械加入操作流程。相关流程图表达起止、角色/系统边界、主要动作、判断分支、异常停点与结果；图文步骤必须一致。复杂流程可拆分总图和局部图，保证Word最终尺寸可读。

缺陷类报告按实际内容呈现总量、分类/分布、状态等统计图表，关联同一版本的缺陷台账。明确统计口径和未分类/待确认项，核对图表与明细总数一致，不凭缺少记录认定零缺陷或全部关闭。保留可维护图源及统计依据，不用无信息装饰图凑篇幅。

### 正式内容与内部记录隔离

正文引用使用明确业务主题；正式文档间追溯允许《文档名称》加经核对的实际章号、表名。避免孤立章号及内部调度话语，保留正式目录、编号和标准条款。

正式文档的正文、引用文件、封面、修订记录、目录缓存、表格、题注、附件、页眉页脚及可见属性不得残留harness内部DOC/XQ/FA/CH编号、R/O/C/D稿次、内部绝对路径或编写调度话语。引用其他交付文档时使用正式文档名称；成果文件名仍按成果规则保留DOC编号。确需正式文件编码或发布版本时，只使用用户确认的正式值，不能拿内部稿次替代。

用于控制写作的文件清单、格式要求及本harness规则仅为内部编写控制依据，不写进正式文档的编制依据或正文；合同、招标和正式业务技术资料可按适用性引用。内部规则、追踪ID、来源版本和哈希仍保留在任务、大纲、复核及知识记录。真实缺陷追踪号、接口字段、业务编号和实际部署命令按用途保留，不使用正则盲删合法内容。

### 全套一致性与交付检查

交付前检查本规范全部有效格式；已有同项目已复核成果时进行比较，无前序成果的新项目直接按确认模板建立基准。封面、目录、标题、正文、表格、题注、页眉页脚和分页方式均应覆盖。比较稿仅作一致性参照，不能覆盖规范或复制其格式错误。检查直接格式覆盖，不只看样式定义。

同步核对总分总、小节深度、步骤与脚本、图文一致、统计与台账、跨文档事实以及内部标识残留。有章节源的新文档回到章节源修改后合并；现有Word修订直接维护当前修订稿，均须渲染最终Word，核验目录实际显示与页码、全部页面及图表可读性。字体替代、原生目录刷新和实际运行验证分别记录真实边界。已复核最新Word在交付结束前按[成果规则](../成果/README.md)同步唯一副本及清单，不等待用户再次提醒。

### 文档定位、成果表述与参考材料


| 文档定位 | 应写内容 | 避免混入 |
|---|---|---|
| 总结报告、改造说明 | 实际开发与处理内容、形成的功能和技术成果、变化影响、应用作用、问题与经验；有依据的结果和简明建议 | 操作步骤、命令教程、核验指南、恢复执行流程，以及重复的方案性流程图 |
| 方案、计划 | 目标范围、条件约束、安排、必要操作流程及判据，明确待实施项 | 未发生的完成结论和实测结果 |
| 手册 | 前提、角色、配置输入、可重复执行步骤、结果与失败处置 | 只有抽象介绍而无操作指导 |
| 部署完成、试运行等实施结果报告 | 实际环境版本、实施记录、结果、证据、遗留问题和交接 | 以计划或安装说明替代完成记录 |

总结说明类同样按总分总组织，但“分”应为具体成果、设计处理、影响和依据，而不是执行指令。建议类章节保留范围、主要建议和总结，不写成另一份试运行或部署方案。必要的验证依据用结果及证据摘要表述；详细命令、离线核查和追踪过程留在内部复核记录或对应操作文档，不因此删掉有效业务结论。

全篇复核应主动检查重复内容、空泛描述、编写和核查话语及文档定位偏移。保留有价值的具体分点，补充有来源的成果描述；同一成果在多章出现时按章节职责说明不同侧面，用摘要和正式名称引用连接，避免重复粘贴。内容深化在已确认目录内完成；结构或实质范围变更仍须更新大纲并确认。

参考其他项目文档时仅提炼章节组织、内容侧重、描述风格和图表呈现方法。禁止移植其项目身份、业务功能、技术实现、环境、数据、性能和验收结论；每项实质主张必须回到本项目资料取证。合同或招标中描述的原有能力可作为有来源的要求/能力比较基线，不代表现场存在旧系统，也不能凭此虚构历史运行结果。

截图须查看实际画面，选取与本节成果直接相关的内容，说明画面呈现的对象、功能及其支撑范围，配正式图题和正文解释；内部记录保存原始来源。先核对版本、敏感信息和最终Word可读性，不凭截图证明性能、完整链路或验收通过。用户明确排除某类截图或调整时，按该文档指令执行，不推广为所有文档的统一排除规则。

### 实施闭环、组件手册与排版细节


**完成状态与问题闭环。** 实施结果报告的概述、环境、实施内容、验证、问题处理与结论应采用一致的实际状态。用户明确确认完成情况时记录原话、范围及来源，并同步相关章节；不得将某项完成扩大为全部测试、正式验收或生产运行通过。部署完成情况使用便于逐项核对的表格，列完成项、实际状态、依据或说明；验证内容按“验证项—验证方法—验证结果”组织，实际需要时涵盖数据库连接、数据完整性、初始化数据和迁移。总结结论应由前文事实支撑，不保留与实际完成状态冲突的未来计划话语。

问题处理采用“问题描述—处理措施—处理结果—当前状态”闭环表，表前有概述、表后有总结。需要详细解释时用加粗问题标题及一段对应处理说明，不机械扩展大量小节，也不写成应急执行方案。只能补充已有记录或用户确认的实际问题；用户要求增加问题数量时先找依据，不能把假设故障写成真实发生。

**组件与业务检查。** 部署和运维手册应核对同一实际组件清单，必要时设置集中章节，每个组件独立子节。运维侧给服务状态、组件健康、日志、配置和失败排查的命令及判据；部署侧给安装配置、启动验证和回退步骤，避免两份手册重复粘贴。除底层组件和进程，还须按适用范围覆盖页面服务可访问性、登录及关键系统功能、业务服务和算法服务链路；进程运行或端口开放不等于业务功能正常。

维护节点、组件、版本、安装/数据/日志目录、服务名和端口对应表，逐项回查已有部署资料和实际代码配置。全篇对应表、命令、正文及图件必须一致；已有材料可确认的参数优先复用，不能自己另定一套。外项目材料只提供组织方法，外项目名称、包名、依赖、服务标识和命令参数不得直接带入。

**分点、命令与占位。** 普通说明段不应出现无来源的项目符号；清理Word样式继承、numPr及转换残留造成的多余圆点。确有并列内容时使用清晰一致的编号或符号，并有前后铺垫；不得把所有真实列表一律删除。

命令、SQL和代码使用可辨识且可复制的独立段落/块，保留换行、缩进和必要空白，不混入正文项目符号，不擅改引号、减号等可执行字符。用统一块样式、边框或浅灰底与正文区分，字体字号及行距仍服从本项目有效规范，不擅用异体字体或缩小字号塞满行；长行在不破坏语法的前提下换行并说明续行方式。最终Word检查命令可读性与源内容一致性，不能只验证MD代码围栏。

清除“（是否存在？）”等未经处理的编辑疑问和占位标识：查明后写确定事实；不适用则按依据删除；无法核实且影响交付时写准确的待确认事项并保留内部缺口记录，不以删除疑问掩盖事实未知。表格有可靠前序文档依据时补齐内容并核对适用范围，不能虚构日期、人员或实测结果。用户明确要求待填写的人员表、签认表等保留空白，不强行补全；项目编号按新项目已确认值填写；只有用户明确要求空白时才留空，不继承来源项目的空值规则。
