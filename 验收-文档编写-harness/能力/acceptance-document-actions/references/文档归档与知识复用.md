# 文档归档与知识复用

## 触发与顺序

“任务完成#”“归档任务#”“任务归档#”为同义标签，统一核验完成、本地成果/知识/进度登记及对应专属聊天归档；用户明确保留聊天时除外。不继承其他项目偏好；单纯生成稿件不等于完成请求。部分交付可按用户明确请求收尾，但必须列明缺章、缺材料与未验证范围，不标全范围通过。

1. 核验任务身份、当前交付版本、约定复核及用户完成请求；新文档另核对O确认和CH/C清单，现有Word修订核对本次授权范围与修改摘要，不强制O/CH；正常完成需约定范围写齐且必需复核通过；用户明确结束当前版本但仍有材料缺口时登记“当前版本交付/范围未齐”，不把缺项算完成。
2. 在任务.md写入本轮归档标识、版本清单、完成模式、范围、证据和遗留项。归档标识使用DOC及D；无合并稿的强制完成使用DOC及已交付CH/C清单摘要，不能虚造D。
3. 创建知识/DOC编号/D版本.md（无D则使用部分交付-批次编号.md），按[成果知识模板](../assets/成果知识模板.md)沉淀内容摘要、主题/关键词、章节定位、资料依据和复用边界。知识记录保留该版本的有效结论，不复制完整正文；章节源和最终稿保留原路径，后续修改新建版本。
4. 更新知识/README.md的DOC行，登记当前有效版本、主题关键词、知识记录和限制；历史知识版本保留替代关系。不另建成果导航文件。
5. 同步工作台账：完成模式、D、完成章数、知识/成果入口、完成时间、归档状态。按DOC更新，重试不重复添加或累计完成数。
6. 检查知识→章节/整稿→依据、工作台账→知识各链接有效，并确保写入成功。完成本地成果登记且归档授权有效后才归档会话；任一步失败保留失败步骤，重试仅补缺失步骤。
7. 核对该DOC绑定的真实threadId/hostId，确认会话归档已授权且专属文档会话的写入工作结束后调用宿主set_thread_archived，记录工具确认的结果。主会话及无关聊天不归档。若在被归档文档会话中执行，先完成全部文件写入，再归档自身；归档状态回写失败可由主会话读取工具状态后补记。

工具不可用或ID不明：本地成果登记可以完成，会话状态记录“待归档”及原因，不虚报成功；没有专属文档会话则记“不适用”。完成后告知成果、知识和进度入口。本流程不要求跨聊天回传消息；如需发送，须有用户明确消息授权，不把归档授权扩大为消息授权。

## 知识需要存什么

至少包括文档目的/适用系统、有效范围、R/O/CH-C/D及F/STYLE、完成及复核状态、核心结论摘要、关键词、每章职责与内容摘要、源文件和标题定位、引用的FACT/REQ/CODE/SRC/IMG及来源版本、相关上下游DOC、未决项、哪些内容可直接参考以及哪些需重新验证。页码仅使用已核验最终格式的真实页码；否则使用章节标题/CH定位。

方案性结论、源码事实和实际运行结果分开标注；知识归档不提升证据等级。敏感参数保留在受控源文件，知识只记定位与用途。强制完成知识条目必须显著注明“部分交付/含未验证项”，不得作为完整通过的依据。

## 后续文档检索与变更

规划新文档先按DOC关系、主题关键词检索知识/README.md，再读取命中的知识记录及相关原章节；无需重读全部归档文档。复用时核对适用系统、版本、证据和限制，登记来源DOC/D/CH/C及使用位置。

已归档文档修订时沿用原DOC和会话，按用户修订请求恢复/解除归档；旧知识版本保留，当前导航标记修订中。新D完成归档后更新最新入口；已引用旧版本的其他文档登记待复核，不自动覆盖其正文。归档文件保持可检索，聊天归档不删除文件。
