# 新文档：需求—大纲方案—章节执行

本文件的大纲确认、CH/C及逐章合并流程仅适用于新文档。现有Word修订按修订#、会话规则和定向修订规则实施，不强制生成大纲或章节源。

## 需求

先核对用户实际要求的文档名称和范围，仅为明确选定的文档创建DOC目录、任务.md和需求/需求.md，同时登记工作台账。已有目录则复用；普通咨询或候选列举不创建。有正式清单时沿用其模板编号，未提供时分配项目内稳定DOC编号并查重。文档关联仅用于查资料，不能据此自动新增交付文档。为每个DOC分配稳定需求编号XQ-三位流水号及对应方案编号FA-同号，先查工作台账和任务记录取未使用号，保留已有编号且不回收归档号。方案编号可在需求登记时预留，明确“未生成”，不提前创建大纲。记录范围、系统、交付格式、源条款、共用资料、未决事实与R版本。分配编号时持工作台账锁重新读取已用号，连同任务映射一次登记，避免多个会话争用流水号。编号登记在现有台账/任务和需求文件中，不新增编号目录或独立编号台账；需求回复必须给出两个编号与可复制的方案#指令。只讨论不自动启动。前期内容分析允许读取原文和代码，不生成未确认正文。

## 方案与会话

方案# XQ-编号通过工作台账定位该需求及对应DOC；方案# FA-编号用于生成或调整同一方案，也兼容DOC编号/文档名。精确匹配编号，不用流水号推定DOC模板编号；找不到编号时不自行新建同名任务。XQ/FA标识文档级需求与方案，R/O标识修订版本，REQ仍标识具体要求条款，三者不混用。

选定文档进入方案阶段时，按用户明确要求建立或复用独立文档会话，否则沿用当前会话，按恢复规则交接；方案/大纲.md是唯一当前大纲，修订履历保留O变化。大纲包括全部章节和下级标题、各章目的/内容边界、依据条款及SRC/CODE/IMG、拟用图表、待补事实、章间关系、逐章交付顺序和判据。技术设计类按技术设计专项的结构规则；其他类映射源文件要求。

方案完成后向用户展示并链接该大纲，明确等待确认。确认字段记录用户原话、时间、确认O版本和范围；无确认不写新文档正文。用户已明确提供并授权执行目录时保存该目录为当前O并登记确认，不要求重复发标签。仅确认部分章节则执行限于确认部分。改动章节顺序、增加/删除章或实质范围后递增O，登记影响章节并重新确认；已写章节保留，标待修订。

## 执行

通过确认门槛后建立执行/章节清单.md。每个一级章使用稳定CH编号（与显示章号分别记录），可按用户要求细分；章目录确认后固定本次粒度。清单包含顺序、显示章号、CH、标题、源路径、C版本、对应O、状态、依据、复核与缺口。

一次编写一个章节文件：读取该章依据和必要相邻章节→落地CH文档→核对下级标题及事实→记录该章C版本与状态。连续全章授权允许按此循环完成，不先生成整篇再拆文件。正文未知项明示待确认；用户指定章节Word则按统一格式逐章输出，并记录与MD源对应关系。

前置封面/修订记录等保存执行/前置页.md，目录由最终标题生成。已确认章结构不应任意扩张。章节修订递增C，使引用该章的合并D和复核标记过期；需求或大纲变更影响其他章节时列出受影响CH，不静默复用旧正文。
