# 文档会话与恢复

一个DOC一个会话覆盖需求、大纲调整、章节执行及合并，不为每章新建会话。新文档按用户要求选择会话；修订#请求创建或复用该文档专属聊天并交接本次明确要求。已在专属聊天则直接承接，不递归新建。只处理当前目标，不批量创建未选定文档的聊天。创建前查工作台账，有有效绑定则复用。

新建使用宿主create_thread，标题“DOC编号：文档名”，传入harness绝对路径、任务路径、共用索引、工作模式、当前版本、授权范围和未决项（新文档另含大纲O/确认）；不指定模型/推理强度，沿用用户设置。create_thread前按工具要求查询项目；文档聊天归入当前实例所属项目，不因harness子目录不同而创建无项目聊天；项目身份从本实例项目配置及宿主列表核对，不写死模板项目ID。只有用户明确要求独立无项目工作区时使用projectless。创建后登记真实ID并做一次有界wait_threads确认进度；创建失败保存手动摘要，不虚报开启窗口。后续向该会话发送工作指令须有用户明确消息授权；用户要求回传同样明确记录，内部消息本身不授权回信。

新文档方案会话仅授权已指定的方案工作，不能提前跨越大纲确认生成正文。用户在该会话直接确认可记入任务；跨会话授权仅接受直接用户消息或工具读取的可信用户确认，记录来源，不将助手转述当确认。

恢复先读任务摘要及最新编写规范；新文档再读O确认和章节源，现有Word修订读取最新Word、当前要求和相关依据。核对当前文件与摘要，过期则按事实更新。共享台账写前重读增量合并。知识正文放知识/，任务只引用；项目级不保留开发分支、代码测试计数、工作树或实现功能进度。

完成收尾遵循[文档归档与知识复用](文档归档与知识复用.md)：先保存本地知识及进度，再归档绑定文档会话。任务完成#/归档任务#/任务归档#按统一语义授权收尾及归档；用户明确保留聊天时覆盖默认行为；恢复先读取任务归档控制区，重试只补未完成步骤。归档后的修订沿用原DOC及会话，旧版本知识保留。

新建/恢复交接只传递harness及任务绝对路径、目标DOC、工作模式、当前交付版本、授权范围及缺口（新文档另含O确认），要求读取资料/项目.md、资料/编写规范.md和目标任务；共性规则引用唯一规范，不复制可能过期的参数。创建/发送失败逐项登记真实结果，恢复先查已有绑定及宿主归档状态，不能因部分中断重复建会话。

进度核对读取成果实物及哈希、最新任务/知识和宿主可验证状态，区分在编、待确认、待归档、已归档但资料未齐。不得凭旧“待归档”文字重启已归档任务。用户只问状态则只读汇报；明确要求核对整理台账时可修正过期记录，不因此执行归档或发消息。

用户明确修订请求授权专属聊天创建/复用及本次具体要求交接；不扩大为向其他聊天发送消息或内部回信授权。只创建会话或只读分析时不修改Word；具体范围未给出时在专属聊天澄清。失败记录真实状态，不在主聊天同时修改同一文档。默认短摘要接续，不继承整段历史。
