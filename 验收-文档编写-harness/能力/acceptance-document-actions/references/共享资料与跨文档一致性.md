# 共享资料与跨文档一致性

从harness根目录读取资料/项目.md、资料/编写规范.md，以及资料/README.md。根据目标DOC读取文档关系行及命中的代码/材料索引；不要求用户重发已登记路径。

定位源文件后核对相关提交、文件哈希及实际段落/类/接口/图像。读取素材不等于完成验证；资料索引可标已定位、已阅读、已核对、失效，证据目录登记实际证据范围。截图必须看到画面后才能描述其功能，不凭文件名宣称功能通过。

新事实归入共享项目事实，任务引用FACT；接口、表、风险、用例、缺陷等名称和编号统一，冲突登记来源及受影响文档，不静默覆盖。更新共用口径/格式/目录时记录F/STYLE/O变化，在工作台账标记受影响稿件待复核。

每个任务记录使用的CODE/SRC/IMG、F/STYLE/O及R/O/C/D；交付前检查上游关联文档，依据不一致时说明缺口。资料变更仅刷新相关条目，保留来源和旧稿复核关系；不将整个代码仓库或敏感配置复制进共享资料。

已有文档成果优先检索知识/README.md。按主题找到知识摘要、CH/C源章节与DOC/D完整稿，核对复用边界后引用；完成时按文档归档与知识复用规则更新这些入口。

## 知识#：补充或更新资料目录

输入为一个或多个目录/文件路径及用途，也可以引用已登记的项目名称要求刷新。无需绑定DOC。无路径但现有上下文能唯一定位时复用；无法定位再询问，不猜测同名目录。

1. 核对路径存在、可读、实际类型及用户说明的用途。不可访问时记录“待定位/不可访问”及原因，不宣称已建立可用索引。
2. 检索现有登记，按实际路径去重；已登记则增量更新原记录，稳定CODE/SRC/IMG编号不重排。路径迁移保存原位置、替代关系及影响，未明确替代的不同项目不覆盖旧项目。
3. 代码目录写入资料/代码索引.md：项目路径、语言/模块、构建或入口文件、版本/提交及工作区状态、可检索主题、核对程度。代码只读，先定位关键结构，按用户要求深读；不默认构建、运行或扫描全部依赖资源。
4. 文档/截图等写入资料/材料与截图索引.md：目录入口及用途、相关文件/主题、版本或文件哈希、适用范围和核对状态。目录本身可用SRC编号，大小/哈希不适用则注明；大目录先登记分类和关键文件，记录覆盖范围，不把局部检索写成全量核验。跳过临时、缓存及无关生成文件。
5. 项目主路径或事实变化更新资料/项目.md；只有实际读取并形成结论才写资料/证据与需求.md。仅发现文件记“已定位”，阅读记“已阅读”，核实后才记“已核对”；截图描述需查看画面，不凭名称判断。
6. 汇报新增/更新入口、主要用途与尚未核实部分。只有影响已有文档时才在工作台账标记待复核；不会因资料登记增加业务任务或完成计数。

知识#登记原始来源，成果归档沉淀已完成文档知识；两者共用现有资料与知识入口，默认不复制原目录；用户明确要求归档依据时可复制选定只读原件，核对来源和副本SHA-256，登记两个路径、版本及替代关系，跳过临时锁文件；不另建“知识投递”或同义索引目录，不将项目事实写入技能。
