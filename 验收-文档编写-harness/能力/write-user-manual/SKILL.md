# 用户操作手册

核对资料/编写规范.md、当前任务与确认大纲；用户交回Word时先读取其实际修改。编排、版本及恢复沿用同级文档任务技能，定向修订沿用原目录。结构及格式细节统一见[编写规范](../../资料/编写规范.md)，不另建状态文件。

按读者业务目标构建场景，说明参与角色、起点、前提、跨菜单活动、阶段产物、完成判据和异常恢复。场景数量按覆盖需要，不固定为某项目的四个场景。来源数据、业务数据、处理任务、结果及发布对象按该项目实际划分，保存、确认、提交、下载、审核等动作不得混为一谈。

无专门目录时建议功能节最多三级标题；用户确认的目录优先。按内容适用性采用四项正文分段：功能说明、界面与字段说明、操作步骤、规则与限制，标签后接同段说明；入口、所需角色按用户已认可功能节统一。步骤引导语按项目规范加粗；采用问答形式时答案标签保持一致。用户要求丰富内容时补充有效业务描述，不拆细碎子标题。

每个操作单元核实目的、角色与权限、前置状态、菜单入口、输入/参数、步骤、等待与失败状态、可观察结果、下一步和恢复。处理步骤的执行操作与结果查看分别放入适用段落，不能用这两个维度替代整个功能结构。字段的必填性、单位、范围、默认值、依赖和重做影响必须有依据，未知项留内部缺口。

代码仅用于内部业务理解和实现核对，正文用业务逻辑及算法作用解释输入、处理与输出，不含代码、编程语言实现、类/函数名、源码路径、接口实现或完整JSON。业务算法名、界面字段、文件格式及单位可保留；截图中的技术详情按读者用途处理，裁切或脱敏留原图关系。

截图必须实际查看，名称只作定位；关联步骤、图号、图题、采集日期和系统版本。使用真实采集信息，不把文档生成日期当采集日期；长清单增加列后核对列宽、重复表头与换行。图表已有题注先识别，避免重复。

模板提供结构和样式，不提供项目事实。复核以新读者能照文完成流程为判据；静态实现、界面观察及运行验证分别记录。文档复核不默认执行上传、写库或系统测试，也不宣称项目验收批准。
