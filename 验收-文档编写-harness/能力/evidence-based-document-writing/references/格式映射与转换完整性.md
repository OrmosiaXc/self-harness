# 格式映射与转换完整性

用户要求Word、套用模板、整稿合并或评审转换结果时读取。格式参数及转换细节统一读取harness下的资料/编写规范.md。先核对实际模板与源格式再使用对应文件技能；本参考不依赖外部spec-delivery脚本。

1. 对本轮采用的模板登记版本/哈希及语义样式映射，用[映射记录模板](../assets/样式映射与转换记录模板.md)记录实际采用项。按需填入现有复核记录，不再建项目状态库。
2. 明确编号唯一来源、真实Heading层级、按项目确认级数的TOC、分节/页码策略、表格列对齐与图宽上限。纯样式模板也要检查残留页眉页脚、属性、关系和内嵌资源，不能把正文为空当作已经清理完毕。
3. 若转换器自动丢弃引用块或章节，检查是否误删正式内容；按需输出评审稿和正式稿，正文一致。业务文件名、技术说明、示例或待确认项的保留由实际文档用途决定。
4. 使用源CH/C清单核对输出的章节、表格、图件、引用和未决项；缺图不能只写占位后记成功。没有图片/表格的文档不强造这些元素。
5. 按图文与交付检查完成结构和全页视觉复核，问题以位置、依据、处置及版本记录。转换报告、脚本返回0和域已插入均不替代最终可见效果核验。

体裁参考：流程内容可用“角色—动作—条件—产出—异常”检查是否可执行；对象/接口内容可用“名称—含义—类型—必选条件—重复次数—值域—约束/枚举来源”检查是否完整。仅作为覆盖维度，不规定八列表格或固定章序；数据库详设允许真实实现类型，手册允许自然操作语言。

源技能引用的标准号、条款与合规结论未经适用性核验，不作为项目规范依据。实际文档要引用时另行核验适用标准、版本及条款，不能继承源项目术语、SYC编号或标准合规声明。
