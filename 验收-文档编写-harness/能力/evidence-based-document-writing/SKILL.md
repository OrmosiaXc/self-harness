# 基于依据的文档编写

处理“如何取证、写好一章和检查稿件”。文档目录、会话、大纲确认、逐章执行和完成归档由同级[文档任务编排](../acceptance-document-actions/SKILL.md)负责，不另建工作区或状态机。用户最新要求及harness共用格式优先。

## 按需加载

| 当前工作 | 读取 |
|---|---|
| 识别资料、阅读源码、核实主张 | [资料与证据](references/资料与证据.md) |
| 参照历史样本、套用指定模板 | [样本与模板提炼](references/样本与模板提炼.md) |
| 实施、测试或验收结果报告 | [报告写作](references/验收报告写作.md) |
| 交付修订与安全替换 | [版本与交付](references/版本与交付管理.md) |
| 写作或评审章节 | [章节写作与深度](references/章节写作与深度.md) |
| 修改某章、控制影响和保存预览 | [定向修订](references/定向修订.md) |
| 模板映射、MD到Word与防止转换漏项 | [格式映射与转换完整性](references/格式映射与转换完整性.md) |
| 图件、DOCX生成与交付复核 | [图文与交付检查](references/图文与交付检查.md)，并读取实际格式技能 |

开始时从harness资料总索引、成果知识和目标DOC任务取得路径、当前R/O、用户确认和所选CH。确认前只做取证与大纲，不生成正文。确认后逐章取证、写作、检查，记录来源与C版本；在已授权范围内持续推进。

依据表和检查结果写入现有证据目录、任务需求/方案/复核记录，不重复建立一套资料库。需要细化时参考[取证与审阅记录模板](assets/取证与审阅记录模板.md)，仅填写本次适用部分。

交付正文写读者需要的业务/技术内容。内部路径、取证编号和处理过程留在内部记录；正式引用名称、业务文件名、接口字段和部署命令是否出现由文档用途决定，不能一律禁止。资料不足必须保留缺口，不把方案或代码静态存在描述成运行通过。
