# 验收文档编写 Harness 使用说明

本 Harness 用来整理项目资料，并按文档逐份编写、修改和检查验收材料。用户只需准备项目资料、选择要写的文档，并按示例向 Agent 提示；任务记录和过程文件由 Agent 放入对应目录。

## 目录是做什么的

| 目录 | 用途 |
|---|---|
| `资料/` | 项目名称、交付文档清单、格式要求、合同/需求、代码和截图等共用资料索引。开始时先填写这里。 |
| `能力/` | Agent 写不同文档时使用的工作规则：任务编排、依据写作、概要设计、用户手册。 |
| `文档/` | 每份文档的工作区。每份文档单独一个 `DOC-编号-名称/` 目录，保存需求、大纲、章节和复核过程。 |
| `工作台账.md` | 所有在编文档的进度总表。查看哪些文档待确认、在编、待复核或已交付。 |
| `知识/` | 已完成文档的摘要和章节索引，便于后续文档复用。 |
| `成果/` | 每份文档最新且已复核的 Word 文件及其版本、哈希记录。 |
| `AGENTS.md` | 本 Harness 的详细工作规则，通常由 Agent 自动读取。 |

资料子目录说明：

| 文件 | 记录内容 |
|---|---|
| `资料/项目.md` | 项目名称、系统范围、实际需要交付的文档、排除项和成果位置。 |
| `资料/编写规范.md` | 字体、标题、表格、图题、页码及共用写作要求。正式模板或用户要求优先。 |
| `资料/证据与需求.md` | 需求/结论对应的资料来源及核对状态。 |
| `资料/代码索引.md` | 代码仓库位置、模块、入口和核对范围；源码默认只读。 |
| `资料/材料与截图索引.md` | 合同、历史文档、模板、截图等材料在哪里以及用途。 |
| `资料/文档关系.md` | 各文档分别负责什么内容，以及一份文档变化会影响哪些其他文档。 |

## 开始使用

1. 在支持项目指令和文件操作的智能开发工具中打开本 Harness 所在的项目目录。
2. 将项目资料放在合适位置，或登记其路径；不要把资料路径当作 Agent 已经阅读过资料。
3. 填写 `资料/项目.md` 中的项目身份、文档清单和排除项，并确认 `资料/编写规范.md`。
4. 只启动实际需要的文档。每份文档分别编号、分别跟踪，不需要的文档不会自动创建。
5. 查看 `工作台账.md` 获取进度，最终 Word 在 `成果/` 中查看。

## 提示词和使用案例

提示词中的 `#` 用半角符号。编号由 Agent 按工作台账分配；也可直接用自然语言明确要求。

| 想做什么 | 提示词 | 使用案例 |
|---|---|---|
| 登记/更新项目资料 | `知识# 资料路径及用途` | `知识# /Users/me/project/src 这是本项目源码，请只读分析模块结构` |
| 新建一份文档任务 | `需求# 文档名称、读者和范围` | `需求# 编写项目验收测试报告，读者为验收组，覆盖本次已执行的功能测试` |
| 生成或调整文档大纲 | `方案# XQ-编号` | `方案# XQ-001` |
| 修改大纲或某章 | `调整# 修改对象及要求` | `调整# 大纲第3章增加接口验证内容，说明与第4章的边界` |
| 确认大纲 | `确认# FA-编号 O版本` | `确认# FA-001 O1` |
| 确认大纲并开始写 | `确认# FA-编号 O版本 并执行范围` | `确认# FA-001 O1 并执行全部章节` |
| 开始写章节 | `执行# 全部章节或指定章节` | `执行# 编写已确认大纲的第1章和第2章` |
| 修改已有 Word | `修订# 文档路径/名称，修改位置、要求和依据` | `修订# 验收报告.docx；修改位置：3.2节；要求：补充失败用例处置；依据：本次测试记录` |
| 复核文档 | `复核# 检查对象和范围` | `复核# 检查验收报告的需求覆盖、证据对应、图表统计及Word分页` |
| 合并章节生成 Word | `合并#` | `合并# 全部章节已完成，请生成Word并完成渲染复核` |
| 查询文档进度 | `进度#` | `进度# 汇总当前在编、待确认大纲、待复核和已交付文档` |
| 完成并归档文档任务 | `任务完成# DOC-编号或文档名` | `任务完成# DOC-001` |
| 按当前实际情况部分收尾 | `强制完成# DOC-编号及未完成项` | `强制完成# DOC-001 第5章未完成，Word仅作为部分交付，请登记缺口` |

## 新文档怎么写

常见操作顺序：

```text
知识# 登记资料 → 需求# 选定文档 → 方案# 生成大纲 → 确认# → 执行# → 复核# → 合并# → 任务完成#
```

大纲未确认前，Agent 先做资料梳理和大纲，不会直接写新文档正文。用户已经给了完整目录且明确授权执行时，可以在任务记录中标明已确认。章节通常先各自保存为 Markdown，再合并成 Word。

## 修改已有 Word 怎么做

已有 Word 不必重新生成整份大纲。使用“修订#”，指出要修改的章节/表格、修改要求和依据。Agent 会保留原稿，制作修订版，并检查修改范围和 Word 排版。如果只想分析或新建修订任务，要明确说“只分析/只创建任务”，避免误解为立即修改。

## 一份文档工作区里有什么

```text
文档/DOC-编号-名称/
  任务.md             这份文档的目标、范围和当前状态
  需求/               文档需求和依据
  方案/大纲.md         章节目录、每章写什么及大纲确认版本
  执行/章节/           各章 Markdown 正文
  复核/               内容、证据和格式检查记录
  合并/               Word 合并与最终检查过程
```

目录按任务实际需要创建，不需要手工把所有空目录建出来。修改意见和新增材料统一放在 Harness 顶层 `资料/` 或 `文档/DOC.../` 对应记录中，并在提示词里说明。

## 去哪里查看结果

- 全部文档进度：[`工作台账.md`](工作台账.md)
- 最新已复核 Word：[`成果/README.md`](成果/README.md) 及其列出的文件
- 完成文档的摘要和章节索引：[`知识/README.md`](知识/README.md)
- 所有资料入口：[`资料/README.md`](资料/README.md)
- 标签的完整定义和更多复制范例：[`提示词说明.md`](提示词说明.md)

“复核通过”指文档内容和格式检查范围内的结果，不等同于系统测试通过或项目验收批准。资料缺失、未经核实的结论和未完成章节应在文档或台账中明确标出。
